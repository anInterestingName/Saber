## 2. 测试范围与使用说明

### 2.1 测试目标

- 验证字典、部门、菜单、角色、顶部菜单、用户和代码生成 7 个页面完成纯 Element Plus 迁移后，
  原菜单入口、接口、字段、权限、租户归属和业务结果保持一致。
- 验证非分页树、详情与远程选项竞态、三类授权树、内联排序、用户联动、上传下载和代码生成副作用
  具有明确且可恢复的成功、失败、取消和重复操作状态。
- 验证第一、二阶段共享能力和仍使用 Avue 的第四阶段代表页面未被第三阶段共享改动破坏。
- 验证 1440px、1024px、375px、浅色/深色/自定义主色、键盘流程、类型检查、生产构建和静态依赖门禁。

### 2.2 范围内

- 页面：`system/dict`、`system/dept`、`system/menu`、`authority/role`、`system/topmenu`、
  `system/user`、`tool/code`。
- 接口：需求与详细设计第 6 节列出的现有列表、详情、树、提交、删除、授权、导入导出、复制和生成接口。
- 回归：第一阶段参数、岗位；第二阶段至少一个分页 CRUD 和一个只读/工具页面；第四阶段数据权限、
  API 权限或区域代表页。
- 工程：静态引用、TypeScript、生产构建、依赖差异、主题与响应式。

### 2.3 不测试内容

- 不验证数据库结构变更；本需求不涉及数据库设计或迁移。
- 不修改或评审用户导入模板字段、默认密码、覆盖策略、导出字段和代码生成模板内容。
- 不验证第四阶段页面的完整业务，只做与第三阶段共享能力相关的兼容冒烟。
- 不对后端导入跨批事务或代码生成文件写入实现作前端自动回滚验证；只记录可观察副作用和限制。
- 所有页面测试统一使用当前环境默认账号 `admin`；不准备或使用任何其他账号。
- 不使用生产数据库、生产生成目录或无法精确清理的业务数据。
- `admin` 无法提供的“权限缺失”和“非管理员服务端拒绝”负向证据只做静态权限映射检查，不以默认账号
  结果代替多角色安全验收；若发布门禁仍要求运行态证据，应另行放宽本次单账号约束后补测。

### 2.4 结果填写规则

正式结果只使用：`未执行`、`通过`、`失败`、`阻塞`或`不适用`。

| 结果 | 使用条件 |
| --- | --- |
| 未执行 | 尚未开始或未完成全部步骤 |
| 通过 | 全部步骤与预期一致，证据完整且清理完成 |
| 失败 | 实际结果不符合预期，已登记缺陷编号 |
| 阻塞 | 缺少账号、权限、数据、环境、工具或人工确认，无法继续 |
| 不适用 | 经需求、技术和测试负责人确认，本环境不需要执行 |

每条用例的“实际结果”与“证据/缺陷”在执行后填写。不得用静态检查替代浏览器业务结论，也不得用
类型检查替代生产构建或真实接口验收。

## 2. 使用说明

### 2.1 结果填写规则

每条用例执行后，将“结果”中的 `未执行` 改为以下值之一，并补充证据或缺陷编号：

| 结果 | 使用条件 |
| --- | --- |
| 通过 | 实际结果完全符合预期，且无影响验收的问题 |
| 失败 | 实际结果与预期不符，已经登记缺陷 |
| 阻塞 | 因环境、账号、数据或外部服务不可用而无法执行 |
| 等待人工 | AI 因验证码首次识别失败或高影响步骤缺少人工确认而暂停，人工处理后可继续 |
| 不适用 | 经需求、技术和测试负责人共同确认，本环境无需执行 |
| 未执行 | 尚未开始或尚未完成 |

证据建议使用 `TEST-REQ-2026-002/{用例编号}-{简述}.png` 命名。网络问题应记录请求 URL、方法、状态码和
响应时间，但不得记录 Token、客户端密钥、数据源密码、公告完整 HTML、日志参数或错误堆栈等敏感内容。

### 2.2 建议执行顺序

1. 完成环境、账号和测试数据准备，执行 `GEN-001` 至 `GEN-005`。
2. 按租户、应用、数据源、通知公告、报表、日志的顺序执行页面业务用例。
3. 使用受限账号执行权限用例，再执行失败恢复、竞态和弹窗拦截用例。
4. 执行第一阶段页面和未迁移 Avue 页面回归。
5. 最后执行多视口、主题、类型检查、生产构建和依赖审计。
6. 清理本轮创建的测试数据，填写测试汇总与验收结论。

### 2.3 AI 执行规则

本文允许 AI 使用浏览器和终端逐项执行，但必须遵守以下规则：

1. 默认使用第 3.2 节声明的本地默认账号登录，不自行创建账号、修改密码或扩大权限。
2. 登录验证码只允许 AI 自动识别并提交一次。AI 无法有把握识别，或首次提交返回“验证码不正确”时，立即暂停
   当前测试，不继续猜测、刷新验证码或重复提交。
3. 暂停时保持登录页和当前验证码可见，向人工说明“需要输入当前验证码并完成登录”；人工完成后从原用例继续。
4. 等待人工验证码期间，用例状态记为“等待人工”，不记为失败或阻塞。若人工确认验证码服务不可用，再改记“阻塞”。
5. AI 不得绕过验证码、直接构造登录请求、读取验证码服务内部状态或降低认证配置。
6. 涉及新增、编辑、删除的用例，只操作 `QA-REQ002-` 前缀或人工明确指定的数据；目标不明确时暂停并请求确认。
7. 报表删除、权限账号切换、回滚演练等高影响步骤不满足前置条件时暂停，不得以其他数据或当前脏工作区替代。
8. 每条用例完成后写入结果和证据；发现与预期不符时先记录现场，不自行修改代码，除非另有明确修复指令。

验证码人工干预请求应包含：当前用例编号、当前页面、已尝试次数（最多 1 次）以及人工需要执行的唯一动作。
人工处理完成后，AI 应确认已经登录且当前账号正确，再继续业务测试。

### 3.4 失败与竞态模拟

- 列表、详情、提交或删除失败：在浏览器 Network 面板定位目标请求，使用 Request blocking 临时阻断对应
  `/list`、`/detail`、`/submit` 或 `/remove` URL；用例结束后立即解除阻断。
- 慢请求和连续操作：将 Network throttling 设置为 `Slow 3G`，连续发起两个不同查询或连续打开两条详情。
- 报表弹窗拦截：临时将站点弹窗权限设为“阻止”，完成用例后恢复。
- 失败模拟不得修改真实后端配置、认证头、Token、数据库或共享测试数据。

## 4. 通用与冒烟测试

### GEN-001 原菜单与路由可达

- 优先级：P0
- 关联验收：AC-029
- 前置条件：使用 `ACC-FULL` 登录。
- 步骤：
  1. 依次从原菜单进入工作台/通知公告、系统管理/租户管理、系统管理/应用管理、研发工具/数据源管理、报表管理/报表列表。
  2. 依次进入系统监控/日志管理下的通用日志、接口日志和错误日志。
  3. 观察地址、菜单高亮、标签页和页面标题。
- 预期结果：8 个页面均可通过原菜单进入；路由与原入口一致；无 404、空白页、重复标签或错误菜单高亮。
- 结果：通过
- 实际结果/证据：`ACC-FULL` 已从原菜单进入 8 个目标页面；路由、页面标题、标签高亮正常，无 404、空白页或重复标签。证据：`.playwright-cli/vis-1440-*.png`、`.playwright-cli/vis-1024-*.png` 及页面快照。

### GEN-002 初始加载与统一布局

- 优先级：P0
- 关联验收：AC-001
- 步骤：
  1. 分别刷新 8 个目标页面。
  2. 观察搜索区、列表标题、工具栏、表格、行操作和分页。
  3. 检查 Console 和 Network。
- 预期结果：页面出现一次有效列表加载；loading 最终结束；总数和列表匹配；布局无重叠；控制台无新增报错；
  接口失败时页面仍可刷新重试。
- 结果：阻塞
- 实际结果/证据：大部分页面可加载统一布局，但数据源列表请求 `GET /api/blade-develop/datasource/list?current=1&size=10` 返回 404，报表列表请求 `GET /api/blade-report/report/rest/list?current=1&size=10` 返回 404，无法确认 8 个页面均完成有效列表加载。网络现场未记录 Token 或敏感数据。

### GEN-003 查询、重置、分页和刷新请求次数

- 优先级：P0
- 关联验收：AC-003、AC-006、AC-020、AC-023
- 步骤：
  1. 在有搜索区的页面输入可命中的条件并点击“查询”。
  2. 切换到第 2 页后再次查询，检查页码是否回到第 1 页。
  3. 点击“重置”，检查条件和页码。
  4. 修改每页条数，再点击右上角刷新按钮。
  5. 在 Network 面板按列表 URL 过滤并统计每次操作的请求数和参数。
- 预期结果：查询、重置和改变每页条数均回到第 1 页；刷新保留当前有效查询；每次用户操作只产生一次
  有效列表请求；`current`、`size` 和页面查询白名单正确。
- 结果：阻塞
- 实际结果/证据：租户、客户端、公告和可用日志页已观察查询/重置行为；数据源、报表列表接口 404，日志数据量不足以覆盖翻页和每页容量变化，无法完成全范围请求参数与请求次数核验。

### GEN-004 快速连续查询的最终结果

- 优先级：P1
- 关联验收：AC-004
- 前置条件：Network throttling 为 `Slow 3G`。
- 步骤：在同一页面快速用两个不同条件连续查询，最后一次条件应能辨识结果。
- 预期结果：页面最终只展示最后一次查询对应的数据和总数；较早响应不得覆盖最终结果；loading 正常结束。
- 结果：阻塞
- 实际结果/证据：当前可用浏览器会话未能同时提供 Slow 3G 限速和请求阻断控制，未完成两个不同条件的乱序响应验证，未以正常速度结果替代该用例。

### GEN-005 列表空数据与请求失败恢复

- 优先级：P1
- 关联需求：EX-001、AC-001
- 步骤：
  1. 输入必然无结果的查询条件。
  2. 确认空状态后恢复正常条件。
  3. 临时阻断列表请求并刷新，再解除阻断后重新刷新。
- 预期结果：空数据有稳定空状态且布局不塌陷；失败后 loading 结束，查询条件保留；解除阻断后可恢复加载。
- 结果：阻塞
- 实际结果/证据：在通知公告页输入必然无结果条件后显示“暂无数据/共 0 条”，重置后恢复 4 条且条件清空；独立阻断 `/list`、解除阻断并再次加载的步骤未完成，故整条用例不标记通过。

### GEN-006 按钮权限与服务端最终授权

- 优先级：P0
- 关联验收：AC-002、AC-025
- 步骤：

  2. 使用 `ACC-NONADMIN` 验证客户端、数据源和日志接口不能通过直接请求绕过管理员校验。
- 预期结果：无权限按钮不显示；前端隐藏不替代后端校验；越权请求被服务端拒绝且页面不显示成功状态。

## 2. 测试范围

- 测试目标：验证前端20项验收标准及其页面、请求和拒绝恢复状态链，与后端三级管理范围一致。
- 范围内：两个管理入口、分页、详情、表单、选项、凭据只写、单记录启停/删除、并发、权限与归属、响应式、共享列表及既有入口回归。
- 接口范围：设计第6.1节13个管理接口；上下文/最小候选仅在协同契约确认、实现并补充最终路径后测试。
- 不测试：供应商推理/连接、内部运行读取授权、数据库迁移/行锁、凭据落盘保护、fast档案、任务模型绑定、后端日志及全系统性能压测。
- 后端凭据实际保留/替换效果需引用后端执行者的无敏感值核验结论；仅看credentialConfigured=true不能证明原值保留。缺少该结论时TC-004相应验证不得判为完整通过。
- 后端范围与拒绝结果在前端联调中观察；不能把页面隐藏当服务端越权防护通过。涉及不可通过UI构造的请求，由授权执行者使用受控请求工具验证，不导出认证头或敏感正文。

### 3.1 测试准备与公共执行约束

1. 确认需求/设计评审结论及缺口关闭；将最终上下文/候选路径和实际菜单名称回填本文，再开始业务执行。
2. 由环境负责人提供测试角色授权。view、add/create、edit、delete按用例最小授予；不把管理员身份当全按钮权限，不给浏览器运行读取权限。
3. 每个用例独立准备数据，不强制依赖另一用例通过。代码前缀用`amc_<执行批次>_tcNNN_`，总长度不超过64；不同执行重新分配，不能复用已删除编码。
4. 台账只记录用例、资源ID、租户、所有人、编码、状态、版本和清理结果；不记录密钥、Token、账号密码或完整表单。
5. 清理只允许“台账ID + 本用例前缀 + 已确认归属”同时一致的记录。模型先单删，再供应商单删；每条需确认，失败不扩大删除范围，禁止按模糊前缀批量清理。
6. 删除是逻辑删除且编码仍占用；不宣称物理擦除凭据。仅使用不可运行的测试凭据，遗留数据由后端负责人按获准策略处置并记录，不授权代理自动物理删除。
7. SU/TA/U/RO/NO之间切换涉及共享登录态，相关用例串行且每次重新登录；多会话并发用独立登录会话。本文没有固定自动执行授权。
8. 字典、角色、服务故障准备会影响全局配置，只能在隔离环境由负责人执行和恢复；不得为跑用例停用共享服务或修改真实用户角色。
9. 证据只保存去除敏感信息后的UI截图、接口路径/业务码/字段名摘要与Console结论。不得保存原始HAR、授权头、凭据正文或后端运行VO。

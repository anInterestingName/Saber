## 2. 摘要与目标

### 2.1 摘要

Saber 当前使用 Vuex 4 管理用户、菜单、权限、标签、布局、锁屏、语言和错误日志等全局状态。随着业务页面逐步
迁移至 Vue 3 Composition API 与 TypeScript，现有全局 getter、字符串式 mutation/action、`$store` 和组件外
直接访问方式增加了类型缺口与启动耦合，也使状态管理实现与当前 Vue 3 技术方向不一致。

本需求要求在不改变后端接口、认证协议、权限结果、菜单结构和用户可见行为的前提下，将全部运行时状态管理迁移
至 Pinia，并从依赖、源码、类型声明和锁文件中完全移除 Vuex 4。本次以已提交源码为回退基线，在同一实现批次内
直接完成全部切换，不注册双状态管理，也不保留 Vuex 兼容适配层或字符串式 Vuex 调用。

### 2.2 需求目标

1. 使用 Pinia 统一承载当前 Vuex 的全部有效状态、派生状态和业务动作。
2. 从运行时依赖、锁文件、应用注册、源码调用和类型声明中完全移除 Vuex 4。
3. 保持登录、Token 刷新、401 退出、动态菜单、按钮权限、标签页、keep-alive、锁屏、主题、语言和日志行为一致。
4. 保持现有 Cookie、localStorage、sessionStorage 数据含义和升级兼容，不要求用户因状态框架迁移重新配置界面。
5. 消除 `$store`、全局 getter 和字符串式 `commit/dispatch`，使状态访问具备明确的业务归属和 TypeScript 契约。
6. 建立可以证明“Vuex 已完全移除且关键状态链路未回归”的静态、工程和浏览器验收门禁。

| 指标 | 当前基线 | 目标值 | 统计口径 |
| --- | ---: | ---: | --- |
| 直接 Vuex 运行时依赖 | 1 | 0 | `package.json` 中 `vuex` 直接依赖 |
| 锁文件 Vuex 记录 | 1 个 Vuex 4 解析项 | 0 | `pnpm-lock.yaml` 中 Vuex 包记录 |
| Vuex 状态模块 | 4 | 0 | `user`、`common`、`tags`、`logs` 旧模块 |
| 包含 `vuex` 标识的 `src` 文件 | 34 | 0 | 对 `src` 执行大小写敏感静态检索 |
| 包含 `$store` 的 `src` 文件 | 15 | 0 | 对 `src` 执行字面量静态检索 |
| Vuex 全局 getter 聚合文件 | 1 | 0 | 当前全局 getter 实现 |
| Pinia 覆盖的有效状态域 | 0 | 4 | 用户、公共布局、标签、日志状态域 |
| Must 验收标准通过率 | 未建立 | 100% | 本文验收标准与关联测试文档 |

### 2.3 非目标

- 不修改 SpringBlade 后端接口、请求参数、响应结构、数据库表或业务数据。
- 不修改 OAuth、验证码、SM2 登录加密、认证头、Token Cookie Key、刷新令牌和多租户契约。
- 不因状态管理迁移改变菜单、权限码、动态路由、标签页、主题、语言、锁屏和日志的产品行为。
- 不要求将 `src/page/` 下全部 Options API 组件同时迁移为 Composition API；只完成状态调用替换所需的修改。
- 不在本需求中建设新的通用缓存框架、跨标签页同步服务、服务端状态缓存或离线能力。
- 不以迁移为由顺带修复与状态框架无关的历史业务问题；发现问题应记录并单独评审。
- 不保留模拟 Vuex `getters/commit/dispatch` 的长期兼容层，也不通过重命名继续隐藏 Vuex 使用。
- 不删除历史需求、设计、测试和 Git 记录中对 Vuex 的事实描述；零引用门禁只约束当前运行时代码与依赖。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：需求和详细设计通过评审；当前版本类型检查通过；可获取至少一个有效账号及菜单权限环境。
- 触发入口：应用启动、登录、路由切换、菜单加载、标签操作、全局界面设置、Token 刷新、401 和错误捕获。
- 最终结果：用户继续完成原业务流程，状态由 Pinia 唯一管理，当前运行时代码和依赖中不存在 Vuex。

1. 应用创建唯一状态管理实例并恢复允许持久化的公共、用户、标签和日志状态。
2. 未登录用户进入公开页面或登录页；登录成功后写入认证状态并清理旧标签与锁屏状态。
3. 已登录用户加载用户、角色、菜单和按钮权限，动态注册路由并进入目标页面。
4. 用户在主布局中切换菜单、标签、主题、语言、锁屏和其他界面设置，状态实时更新并按现有规则持久化。
5. Token 到期时执行刷新；请求返回 401 或用户主动退出时清理认证、菜单、权限、标签和锁屏状态。
6. 前端异常继续进入日志状态域，并按现有入口查看、发送或清除。
7. 工程门禁和业务回归全部通过后删除所有临时 Vuex 并行代码，确认最终运行态只有 Pinia。

    I -- 否 --> J[清理会话并返回登录页]
    I -- 是 --> K[加载菜单与按钮权限]
    K --> L[注册动态路由并进入目标页面]
    L --> M[使用菜单、标签、主题、语言和锁屏]

## 5. 功能需求与验收标准

### 5.1 REQ-001 Pinia 成为唯一状态管理运行时

#### 5.1.1 需求说明

- 关联用户故事：`US-001`、`US-004`
- 优先级：Must
- 触发入口：依赖安装、应用启动、工程检查和生产构建。
- 前置条件：四个现有状态域及其调用方均已迁移。
- 输入：当前状态模块、应用入口、依赖和类型声明。
- 处理规则：
  1. 应用只能创建并注册一个 Pinia 根实例。
  2. 实现批次直接切换至 Pinia，不得同时注册、导入或间接封装 Vuex。
  3. 不得保留模拟 Vuex `getters`、`commit`、`dispatch` 或 `$store` 的兼容接口。
  4. 删除 Vuex 直接依赖、锁文件记录和全局类型声明。
- 输出：应用运行时只使用 Pinia 管理全局状态。
- 限制：历史文档中的 Vuex 事实描述不属于删除范围。

#### 5.1.2 验收标准

- `AC-001`：Given 检查 `package.json`，When 搜索状态管理依赖，Then 存在经评审的 Pinia 依赖且不存在 `vuex`。
- `AC-002`：Given 检查 `pnpm-lock.yaml`，When 搜索 Vuex 包记录，Then 不存在 Vuex 4 解析项或仅为兼容而保留的依赖链。
- `AC-003`：Given 检查应用入口，When 启动应用，Then 只注册一个 Pinia 实例且不注册 Vuex store。
- `AC-004`：Given 检查 `src`，When 搜索 `vuex`、`$store`、Vuex `useStore` 和 `mapGetters`，Then 当前运行时代码中无匹配项。
- `AC-005`：Given 检查状态调用，When 搜索字符串式 Vuex `commit/dispatch`，Then 不存在 Vuex 状态调用或兼容分发器。

### 5.2 REQ-002 四个状态域完整迁移

#### 5.2.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-003`
- 优先级：Must
- 触发入口：用户、公共界面、标签和日志状态的全部读写场景。
- 前置条件：当前 Vuex 状态、派生状态、mutation 和 action 已建立迁移清单。
- 输入：当前四个状态模块及全局 getter。
- 处理规则：
  1. 用户状态域覆盖用户信息、角色、权限、菜单、Token 和刷新 Token。
  2. 公共状态域覆盖语言、布局设置、折叠、全屏、菜单显示、搜索、刷新和锁屏。
  3. 标签状态域覆盖首页标签、当前标签、标签列表和 keep-alive 名单。
  4. 日志状态域覆盖错误日志列表、数量、空状态、添加、发送和清理。
  5. 原跨模块 mutation 必须改为明确的状态域协作，不得依赖全局同名字符串分发。
- 输出：四个状态域具有明确边界，全部现有有效状态均有对应承载位置。
- 限制：不得静默删除旧状态或改变默认值；废弃状态必须有无调用证据和评审结论。

#### 5.2.2 验收标准

- `AC-006`：Given 已登录用户，When 读取用户、角色、权限和菜单状态，Then 数据与迁移前同一后端响应一致。
- `AC-007`：Given 主布局已加载，When 切换折叠、布局、主题、语言、搜索、刷新和全屏状态，Then 页面行为与迁移前一致。
- `AC-008`：Given 打开多个业务页面，When 新增、切换、关闭其他或关闭全部标签，Then 当前标签和标签列表符合现有规则。
- `AC-009`：Given 路由标记页面需要缓存，When 离开并返回页面，Then keep-alive 名单和缓存行为与迁移前一致。
- `AC-010`：Given 前端捕获运行时错误，When 查看、发送或清理日志，Then 日志数量、内容范围和操作结果与迁移前一致。
- `AC-011`：Given 登录或退出需要清理其他状态域，When 操作完成，Then 标签、锁屏、菜单和认证状态按现有顺序完成更新。

### 5.3 REQ-003 应用启动与组件外状态访问

#### 5.3.1 需求说明

- 关联用户故事：`US-001`、`US-003`
- 优先级：Must
- 触发入口：应用入口、主题初始化、国际化、路由初始化、Axios 拦截器、权限守卫和错误处理。
- 前置条件：应用共享同一 Pinia 实例。
- 输入：启动时持久化状态、路由、国际化和请求事件。
- 处理规则：
  1. 组件外模块必须访问同一 Pinia 实例，不得隐式创建独立状态树。
  2. 主题和语言在应用首次渲染前读取到有效值，并在无存储值时使用现有默认值。
  3. 动态路由首次注册必须读取当前用户的有效菜单状态。
  4. Axios 401、路由守卫和全局错误处理必须调用明确的状态域动作。
  5. 初始化顺序不得产生循环依赖、重复注册、未激活实例或首次渲染状态闪烁。
- 输出：直接访问、刷新和登录跳转均使用一致的状态实例。
- 限制：不得通过全局变量暴露可变 store 作为初始化顺序的替代方案。

#### 5.3.2 验收标准

- `AC-012`：Given 浏览器直接访问登录页，When 应用启动，Then 语言和主题使用存储值或现有默认值且无 store 初始化错误。
- `AC-013`：Given 已登录且存在持久化菜单，When 浏览器刷新当前业务路由，Then 动态路由正常注册并进入目标页面。
- `AC-014`：Given 任一请求返回 401，When Axios 拦截器处理响应，Then 使用当前唯一状态实例清理会话并跳转登录页。
- `AC-015`：Given 页面渲染发生前端异常，When 全局错误处理器运行，Then 错误写入当前日志状态域且不创建新状态实例。
- `AC-016`：Given 检查控制台，When 完成首次加载、刷新和路由切换，Then 不出现未激活 Pinia、重复 store 或循环初始化错误。

### 5.4 REQ-004 认证与会话行为保持一致

#### 5.4.1 需求说明

- 关联用户故事：`US-002`、`US-005`
- 优先级：Must
- 触发入口：账号登录、第三方登录、手机号登录、Token 刷新、主动退出、401 和前端注销。
- 前置条件：后端认证服务和当前认证配置可用。
- 输入：登录载荷、Token、刷新 Token 和用户信息响应。
- 处理规则：
  1. 保持三条登录链路的请求参数、加密、成功判断和跳转行为不变。
  2. 登录成功后继续写入 Token、刷新 Token 和用户信息，并清理标签与锁屏状态。
  3. Token 刷新继续使用现有刷新令牌，不改变 Cookie Key、存储键和认证头。
  4. 主动退出、前端注销和 401 清理必须覆盖认证、角色、权限、菜单、标签和锁屏状态。
  5. 同一认证失败不得引发重复退出请求、重复消息或重复路由跳转。
- 输出：迁移前后同一认证操作产生相同的用户可见结果和前端会话状态。
- 限制：不得记录密码、Token、刷新 Token、验证码或客户端密钥。

#### 5.4.2 验收标准

- `AC-017`：Given 有效账号和租户，When 完成账号登录，Then 写入既有认证存储并进入原首页。
- `AC-018`：Given 第三方或手机号登录条件可用，When 完成对应登录，Then 沿用现有请求和登录后状态处理。
- `AC-019`：Given Token 达到刷新条件，When 刷新成功，Then 新 Token 与刷新 Token 生效且当前页面和菜单保持可用。
- `AC-020`：Given Token 刷新失败，When 失败被处理，Then 提交锁恢复且不保留错误的新认证状态。
- `AC-021`：Given 已登录用户，When 主动退出，Then 服务端退出完成后清理全部前端会话并进入登录页。
- `AC-022`：Given 请求返回 401，When 自动注销完成，Then 不再显示上一用户的权限、菜单或页面缓存。

### 5.5 REQ-005 菜单、权限、标签与主布局行为保持一致

#### 5.5.1 需求说明

- 关联用户故事：`US-002`、`US-005`
- 优先级：Must
- 触发入口：登录后用户信息、顶部菜单、侧边菜单、动态路由、按钮权限、标签栏、锁屏和设置面板。
- 前置条件：账号具有可验证的菜单与按钮权限。
- 输入：用户、菜单、按钮权限和界面设置状态。
- 处理规则：
  1. 顶部菜单切换继续加载对应菜单并更新动态路由。
  2. 按钮权限继续按现有权限码映射，超级管理员判断语义不变。
  3. 标签添加、关闭、关闭其他、关闭全部和刷新行为不变。
  4. 侧边、顶部和混合布局以及菜单折叠、搜索、锁屏、主题和语言行为不变。
  5. 快速切换用户、租户或菜单时，不得展示上一上下文的权限或菜单状态。
- 输出：用户无法从可见界面和业务结果识别状态框架已经替换。
- 限制：前端权限只负责显示与交互控制，后端仍是最终安全边界。

#### 5.5.2 验收标准

- `AC-023`：Given 登录用户具有多组菜单，When 切换顶部菜单，Then 侧边菜单、动态路由和目标首页与服务端结果一致。
- `AC-024`：Given 普通用户和管理员账号，When 进入权限敏感页面，Then 按钮可见性和管理员专项入口与迁移前一致。
- `AC-025`：Given 页面包含 CRUD 权限控制，When 权限状态变化或重新登录，Then 页面读取当前用户权限而非缓存旧结果。
- `AC-026`：Given 已打开多个标签，When 刷新浏览器或切换路由，Then 有效标签和当前标签按既有持久化规则恢复。
- `AC-027`：Given 设置面板可用，When 切换主题、主色和布局，Then 主布局即时更新且刷新后按现有规则恢复。
- `AC-028`：Given 用户设置锁屏密码并锁定，When 访问其他路由或解锁，Then 路由限制和解锁结果与迁移前一致。

### 5.6 REQ-006 持久化数据兼容

#### 5.6.1 需求说明

- 关联用户故事：`US-002`、`US-005`
- 优先级：Must
- 触发入口：覆盖升级后的首次启动、浏览器刷新、登录、退出和界面设置更新。
- 前置条件：浏览器中可能存在迁移前版本写入的 Cookie、localStorage 和 sessionStorage。
- 输入：现有 Token、用户、权限、菜单、标签、语言、设置、锁屏和日志存储项。
- 处理规则：
  1. 保持仍有效的存储键、存储介质、有效期和数据语义一致。
  2. 迁移不得因为状态框架变化批量删除有效用户设置或强制用户重新配置布局和语言。
  3. 会话级权限和锁屏数据继续遵循现有 sessionStorage 生命周期。
  4. 认证 Cookie 与本地认证镜像必须按现有登录、刷新和退出规则同步。
  5. 无效或缺失数据使用现有默认值，不得阻断启动或展示其他用户状态。
- 输出：迁移前写入的有效状态可被迁移后版本安全读取和继续更新。
- 限制：不保证兼容未被当前代码定义或已废弃的第三方私有存储项。

#### 5.6.2 验收标准

- `AC-029`：Given 浏览器保存迁移前的语言和布局设置，When 首次启动迁移后版本，Then 页面使用相同有效设置。
- `AC-030`：Given 浏览器保存迁移前的有效登录状态，When 刷新受保护页面，Then 不因状态框架变化被无条件退出。
- `AC-031`：Given sessionStorage 中存在当前会话权限和锁屏状态，When 同一会话刷新，Then 状态按现有规则恢复。
- `AC-032`：Given 主动退出登录，When 清理完成，Then 不再恢复上一用户的菜单、权限、标签和锁屏状态。
- `AC-033`：Given 存储项为空或格式无效，When 应用启动，Then 使用安全默认值且控制台无未处理异常。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 最终运行态只能存在一个 Pinia 根实例和一套有效状态源 | 全部前端状态 | 阻止发布，不以兼容层绕过 |
| BR-002 | 本需求不使用 Pinia/Vuex 双运行时中间态，全部调用方与依赖同批次切换 | 迁移批次 | 零引用门禁失败并整体回退 |
| BR-003 | 状态必须由明确业务域拥有，跨域操作通过显式业务动作完成 | 用户、公共、标签、日志 | 代码评审不通过 |
| BR-004 | Token、权限、菜单和用户信息必须属于同一当前会话上下文 | 认证与权限 | 清理不一致状态并重新登录 |
| BR-005 | 前端权限状态不是安全边界，服务端权限校验保持不变 | 全部权限页面 | 沿用服务端拒绝结果 |
| BR-006 | 有效持久化键、介质和语义在本需求中保持兼容 | 升级、刷新和重登 | 使用默认值或兼容读取，不阻断启动 |
| BR-007 | 普通接口错误仍由统一 Axios 链路处理，状态动作不得重复提示 | 全部异步动作 | 保留输入和可重试状态 |
| BR-008 | 迁移不得把密码、Token、权限列表或日志正文输出到调试日志 | 认证、权限和日志 | 删除敏感输出并阻止发布 |

### 6.2 状态与迁移

| 状态 | 含义 | 允许操作 | 可迁移到 |
| --- | --- | --- | --- |
| INITIALIZING | Pinia 创建并恢复允许持久化的状态 | 读取配置、语言、主题和会话 | ANONYMOUS、AUTHENTICATING、AUTHENTICATED |
| ANONYMOUS | 当前没有有效认证会话 | 访问公开页、发起登录 | AUTHENTICATING |
| AUTHENTICATING | 正在登录、刷新或恢复用户状态 | 等待结果、失败重试 | ANONYMOUS、AUTHENTICATED |
| AUTHENTICATED | 用户、菜单和权限上下文有效 | 导航、业务操作、刷新、退出、锁屏 | REFRESHING、LOCKED、ANONYMOUS |
| REFRESHING | 正在刷新 Token | 等待刷新结果 | AUTHENTICATED、ANONYMOUS |
| LOCKED | 当前会话已锁屏 | 解锁、退出 | AUTHENTICATED、ANONYMOUS |

stateDiagram-v2
    [*] --> INITIALIZING
    INITIALIZING --> ANONYMOUS: 无有效会话
    INITIALIZING --> AUTHENTICATING: 恢复用户信息
    ANONYMOUS --> AUTHENTICATING: 发起登录
    AUTHENTICATING --> AUTHENTICATED: 登录或恢复成功
    AUTHENTICATING --> ANONYMOUS: 登录或恢复失败
    AUTHENTICATED --> REFRESHING: Token 达到刷新条件
    REFRESHING --> AUTHENTICATED: 刷新成功
    REFRESHING --> ANONYMOUS: 刷新失败
    AUTHENTICATED --> LOCKED: 用户锁屏
    LOCKED --> AUTHENTICATED: 解锁成功
    AUTHENTICATED --> ANONYMOUS: 主动退出或 401
    LOCKED --> ANONYMOUS: 退出
~~~

### 7.1 资源归属

| 操作 | 是否需要登录 | 业务前置条件 | 失败行为 |

- 作用域：当前用户与租户上下文。
- 当前处理：只迁移权限状态承载和读取方式，不新增角色、权限码或前端安全模型。

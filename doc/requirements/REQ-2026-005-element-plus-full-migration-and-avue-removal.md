## 2. 摘要与目标

### 2.1 摘要

前四阶段已经将业务页面中的 Avue CRUD、Form 和 Tree 迁移为 Element Plus，但仓库仍保留 Avue 运行时、
富文本插件、数据展示专项组件、通用 CRUD 兼容代码，以及主布局和动态路由中的 Avue 命名。当前状态仍需安装、
初始化和维护两套前端能力，无法视为真正完成 Element Plus 全量迁移。

本需求承接第四阶段，在保持现有菜单、接口、权限、租户、通知内容和主布局行为的前提下，替换最后两个 Avue
专项组件，移除 Avue 依赖与兼容基础设施，并清理活动源码中的 Avue 品牌命名。通知公告富文本必须先完成替代方案
评审，替换后不得降级为纯文本，也不得破坏历史 HTML 内容和媒体资源。

### 2.2 需求目标

1. 从运行时依赖、全局注册、业务组件和兼容代码中完全移除 Avue。
2. 为通知公告提供独立于 Avue 的 Vue 3 富文本能力，保持历史内容、常用格式、媒体上传和只读查看兼容。
3. 将 `util/data.vue` 的数据展示能力迁移为 Element Plus 实现，保留原动态菜单路径可用。
4. 清理主布局、动态路由、样式、存储键和可见文案中的活动 Avue 命名，统一使用 Saber 语义。
5. 保持前四阶段页面、登录、菜单、标签页、主题、权限、租户和外链行为不变。
6. 建立可以证明“Avue 已完全移除”的静态、构建和浏览器验收门禁。

| 指标 | 当前基线 | 目标值 | 统计口径 |
| --- | ---: | ---: | --- |
| 直接 Avue 运行时依赖 | 2 | 0 | `package.json` 中 `@smallwei/avue`、`avue-plugin-ueditor` |
| 锁文件 Avue 包记录 | 2 类及其解析记录 | 0 | `pnpm-lock.yaml` 静态检索 |
| Avue 专项活动组件 | 2 | 0 | `avue-ueditor`、`avue-data-pay` 模板引用 |
| Avue 全局初始化 | 2 | 0 | `app.use(Avue)`、`app.use(avueUeditor)` |
| Avue 通用 CRUD 兼容入口 | 2 类 | 0 | `$crudCommon`、`src/mixins/crud.js`、`src/option/crud/` |
| 包含 Avue 活动标识的 `src` 文件 | 32 | 0 | 对 `src` 执行大小写不敏感静态检索；历史文档不计入 |
| 富文本历史 HTML 可读取率 | 待验证 | 100% | 受控历史通知样例查看、编辑、保存、重开 |
| Must 验收标准通过率 | 未建立 | 100% | 本文验收标准与正式测试文档 |

### 2.3 非目标

- 不修改 SpringBlade 后端业务接口、数据库表、认证头、Token Cookie Key、多租户和权限模型。
- 不把通知公告改为 Markdown、纯文本或新的内容数据格式；服务端 `content` 字段继续承载 HTML 字符串。
- 不在需求阶段指定最终富文本编辑器、版本或组件封装细节；选型结论在详细设计中评审。
- 不建设通用低代码 CRUD、表单生成器、页面设计器或富文本内容管理平台。
- 不删除 Git 历史、需求设计文档和测试记录中关于 Avue 迁移过程的事实描述。
- 不因活动源码清理而重写历史发布版本含义；仅处理当前界面仍展示的品牌依赖或误导性文案。
- 不顺带重构范围外业务模块、Vuex 架构、Axios 拦截器或全部 Options API 页面。
- 不新增后端文件上传接口；富文本媒体能力应复用现有受认证资源上传链路，契约不足时另立后端需求。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：第四阶段代码已实现并通过常规工程检查；本需求、详细设计和富文本选型完成评审后方可开发。
- 触发入口：应用启动、登录后主布局、动态菜单、通知公告页面和工具数据展示页面。
- 最终结果：用户使用原菜单和业务流程时不感知 Avue 被移除；安装、构建和运行时不再包含 Avue。

1. 维护者盘点全部 Avue 依赖、组件、全局对象、命名、样式和动态菜单入口。
2. 评审富文本候选方案，使用历史通知样例验证 HTML、格式、媒体、只读和上传兼容性。
3. 替换通知富文本与数据展示专项组件，保持原业务路径和接口结果。
4. 删除全局 Avue 初始化、通用 CRUD 兼容代码和依赖记录。
5. 清理动态路由、主布局、样式、存储键与当前可见文案中的 Avue 活动命名。
6. 执行静态门禁、类型检查、生产构建和关键业务浏览器回归。
7. 全部 Must 验收通过后，归档测试证据并将需求状态更新为已验收。

## 5. 功能需求与验收标准

### 5.1 REQ-001 Avue 运行时与依赖完全移除

#### 5.1.1 需求说明

- 关联用户故事：`US-001`、`US-005`
- 优先级：Must
- 触发入口：安装、应用启动、构建和静态检查。
- 前置条件：全部 Avue 活动组件已有替代方案，通用 CRUD 遗留已确认无调用方。
- 输入：当前 `package.json`、锁文件、应用入口和源码引用。
- 处理规则：
  1. 删除 `@smallwei/avue`、`avue-plugin-ueditor` 及其仅由 Avue 引入的锁文件记录。
  2. 删除 Avue CSS、插件初始化和只为 Avue/旧富文本服务的全局 Axios、CRUD 兼容挂载。
  3. 删除无调用方的通用 CRUD mixin、option 和相关类型声明。
  4. 不得以复制 Avue 源码、私有组件或样式到仓库的方式规避依赖扫描。
- 输出：应用只通过 Vue 3、Element Plus、业务组件和经评审的专项依赖运行。
- 限制：移除动作必须与最后使用方替换处于同一可发布批次，不允许提交不可运行的中间态。

#### 5.1.2 验收标准

- `AC-001`：Given 检查 `package.json`，When 搜索 Avue 包，Then 不存在 `@smallwei/avue` 或 `avue-plugin-ueditor`。
- `AC-002`：Given 检查 `pnpm-lock.yaml`，When 搜索 Avue 包及解析记录，Then 不存在 Avue 运行时或插件条目。
- `AC-003`：Given 检查应用入口，When 启动应用，Then 不导入 Avue CSS、不执行 Avue 或 Avue 富文本插件注册。
- `AC-004`：Given 检查源码，When 搜索 `$crudCommon`、`mixins/crud` 和 `option/crud`，Then 不存在活动引用或遗留实现。
- `AC-005`：Given 删除 Avue 后执行生产构建，When 检查构建产物，Then 不通过隐藏、复制或别名方式重新打包 Avue 代码。

### 5.2 REQ-002 通知公告富文本替代

#### 5.2.1 需求说明

- 关联用户故事：`US-002`
- 优先级：Must
- 触发入口：通知公告新增、编辑和查看弹窗。
- 前置条件：详细设计已完成富文本候选方案对比，并使用历史内容样例验证。
- 输入：通知 `content` HTML、用户编辑操作和待上传媒体文件。
- 处理规则：
  1. 富文本必须是独立 Vue 3 能力，不依赖 Avue 组件、样式、全局对象或私有实现。
  2. `content` 继续以 HTML 字符串与现有接口交互，不改变字段名和提交结构。
  3. 至少保留段落、标题、粗体、斜体、下划线、删除线、列表、引用、链接、图片、视频、表格、清除格式和撤销/重做能力。
  4. 查看模式必须只读，不能因聚焦、切换记录或关闭弹窗修改内容。
  5. 图片和视频复用现有受认证资源上传链路；Token 不得放入 URL，上传失败不得插入失效节点。
  6. 编辑器加载、详情加载、媒体上传和表单提交使用独立状态；任一失败不得把空内容覆盖历史内容。
  7. 历史 HTML 中的常用结构和媒体 URL 必须可查看；不支持的内容应在详细设计中定义保真或阻止编辑策略。
  8. 富文本展示不得执行脚本、事件处理器或危险 URL；前端控制不替代服务端内容安全校验。
- 输出：可新增、编辑、查看并重新打开的公告 HTML 内容。
- 限制：不得以普通 textarea 或手写 `contenteditable` 的简化实现替代完整富文本能力。

#### 5.2.2 验收标准

- `AC-006`：Given 打开新增公告，When 使用最低要求中的文本格式并提交，Then 重开详情后格式与文本保持一致。
- `AC-007`：Given 一条含标题、列表、引用、链接、表格和媒体的历史公告，When 查看，Then 内容可读且媒体引用不被清空。
- `AC-008`：Given 打开历史公告编辑，When 不修改内容直接保存，Then 服务端内容不被空值或默认模板覆盖。
- `AC-009`：Given 查看模式，When 用户点击、选择文字或关闭弹窗，Then 不产生内容更新请求或模型变更。
- `AC-010`：Given 上传图片或视频成功，When 插入并保存公告，Then 重开后媒体可见且 URL 来自现有资源服务返回值。
- `AC-011`：Given 媒体上传失败，When 用户继续编辑，Then 已输入内容保留、失败媒体不插入且可重试。
- `AC-012`：Given 编辑器或详情加载失败，When 用户尝试提交，Then 提交被阻止且原公告数据不改变。
- `AC-013`：Given 富文本包含脚本、事件属性或危险链接样例，When 查看或编辑，Then 页面不执行相应代码。
- `AC-014`：Given 快速切换两个公告详情，When 旧请求后返回，Then 旧 HTML 不覆盖当前公告内容。

### 5.3 REQ-003 数据展示专项组件迁移

#### 5.3.1 需求说明

- 关联用户故事：`US-004`
- 优先级：Must
- 触发入口：动态菜单对应的 `src/views/util/data.vue`。
- 前置条件：核对部署环境是否仍下发该菜单路径。
- 输入：页面内静态展示数据和用户操作。
- 处理规则：
  1. 默认保留原页面路径并使用 Element Plus 重建数据展示。
  2. 页面不得使用 Avue 数据组件、文档链接、品牌图片或购买引导。
  3. 展示内容使用非敏感本地示例，不调用业务写接口，不持久化用户输入。
  4. 如产品决定下线，必须同步移除动态菜单和相关入口，并提供无断链证据。
- 输出：可访问的 Element Plus 数据展示示例，或已批准且完整下线的入口。

#### 5.3.2 验收标准

- `AC-018`：Given 1440px、1024px 和 375px 视口，When 查看保留页面，Then 内容可读、主要操作可达且不横向遮挡。

### 5.7 REQ-007 工程门禁、发布与回滚

- 本需求不新增权限码，不改变 `notice_*`、菜单、权限范围或行政区划权限。

- 前端按钮可见性不是安全边界，移除 Avue 后仍由现有后端接口执行最终认证和授权。

### 9.3 富文本替代方案评审要求

详细设计必须至少比较“直接使用成熟编辑器内核”“无头富文本编辑器”和“其他 Vue 3 编辑器”三类候选，候选可
包括但不限于 WangEditor、Tiptap、Quill 的 Vue 3 适配方案。评审不得只比较演示效果，至少覆盖：

| 维度 | 必须回答的问题 |
| --- | --- |
| 历史 HTML 兼容 | 现有公告的标签、属性、表格、图片和视频能否保真读取与再次保存？ |
| Vue 3 与 TypeScript | 是否有明确的 Vue 3 生命周期、只读、销毁和类型支持？ |
| 媒体上传 | 是否支持接入现有 Axios 与资源上传响应，不暴露 Token？ |
| 内容安全 | 对 script、事件属性、危险链接和粘贴内容如何处理？ |
| 工具栏能力 | 是否覆盖本需求最低格式集合，移动端是否可操作？ |
| 包体与加载 | 是否可按页面加载，新增体积和依赖树是否可接受？ |
| 维护与许可 | 维护状态、许可证、升级风险和已知安全问题是否可接受？ |
| 迁移与回滚 | 是否可以在不改后端数据的情况下替换和回滚？ |

选型结论必须附历史内容样例验证结果和未兼容清单。存在会静默丢失内容的差异时，不得进入实现阶段。

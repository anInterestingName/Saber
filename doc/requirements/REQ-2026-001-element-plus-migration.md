## 2. 摘要与目标

### 2.1 摘要

Saber 当前有 21 个页面使用 `avue-crud`。用户管理界面的改版已经出现 Element Plus
搜索与工具栏、Avue 表格与表单并存的页面内混合模式，继续沿用将增加状态、权限、插槽和样式的维护成本。
本需求建设一组轻量 Element Plus 通用组件和状态 composable，并按页面渐进迁移，最终形成可持续的纯
Element Plus 管理页面范式。迁移后的组件和页面以 Ant Design Vue 后台管理界面作为视觉与交互基准，
同时保持现有业务、权限、接口和未迁移页面稳定。

### 2.2 需求目标

1. 为搜索、列表容器、分页、表单弹窗和标准字典建立统一的 Element Plus 复用能力。
2. 将分页加载、选择状态、远程选项和标准 CRUD 权限从页面重复代码中提取为类型明确的 composable。
3. 通过简单 CRUD 页面和字典/树选择页面验证迁移范式，再迁移用户管理等复杂页面。
4. 迁移过程中保持菜单入口、按钮权限、租户行为、API 参数、数据结果和用户反馈不变。
5. 使用 Element Plus 实现 Ant Design Vue 风格的搜索、列表、工具栏、表单和反馈体验。
6. 不新增第二套基础组件库，不以声明式配置重新实现一套通用 CRUD 引擎。

| 指标 | 当前值 | 第一阶段目标值 | 统计口径 |
| --- | ---: | ---: | --- |
| 使用 `avue-crud` 的页面数 | 21 | 至少减少 2 个 | `src/views/**/*.vue` 静态检索 |
| 纯 `el-table` 业务页 | 0 | 至少 2 个 | `src/views/**/*.vue` 静态检索 |
| 新增运行时依赖 | 0 | 0 | `package.json` 与锁文件 |
| 试点页面类型检查通过率 | 不适用 | 100% | `pnpm run type-check` |
| 试点页面核心流程通过率 | 未建立 | 100% | 本文验收场景 |
| Ant Design Vue 视觉基线覆盖率 | 未建立 | 100% | 搜索、列表、分页、弹窗和状态截图评审 |

### 2.3 非目标

- 第一阶段不一次性迁移全部 21 个 Avue 页面。
- 第一阶段不移除 Avue 包、Avue 主布局、富文本插件或未迁移页面的 Avue 用法。
- 不引入 Ant Design Vue 或其他基础组件库作为运行时依赖；Ant Design Vue 仅作为视觉与交互参考。
- 不改变 SpringBlade 后端接口、数据库结构、认证头、Token、租户契约和权限码。
- 不建设通过列 JSON 自动生成表格和表单的通用 CRUD 引擎。
- 不在本需求中新增单元测试或端到端测试基础设施。

### 3.1 用户故事

| --- | --- | --- | --- | --- |

| US-002 | Must | 作为前端开发者，我希望使用明确的 Element Plus 组件和组合式状态完成页面，以便不再同时维护 Avue option 与自定义界面。 | 新建或迁移标准管理页面 | 通用组件与 composable |
| US-003 | Must | 作为维护者，我希望页面可以逐个迁移且未迁移页面不受影响，以便控制发布风险。 | 分批发布、故障回滚 | Avue 与 Element Plus 过渡共存 |
| US-004 | Should | 作为测试人员，我希望所有迁移页面具有一致的加载、空数据、失败和提交反馈，以便按统一标准验收。 | 桌面端、移动端、明暗主题验证 | 页面状态规范 |

### 3.2 范围内

- 增强现有 `search-panel`，支持可配置操作区、展开状态和加载态。
- 新增 `list-panel`、`list-pagination`、`form-dialog`、`dict-select` 和 `dict-tag`。
- 按实际迁移需要建设 `row-actions`、`detail-drawer` 和 `blade-upload`，不要求第一阶段一次完成。
- 新增分页列表、表格选择、远程选项和标准 CRUD 权限 composable。
- 新增分页、选项和 CRUD 模式等共享 TypeScript 类型。
- 第一阶段迁移参数管理作为标准分页 CRUD 试点。
- 第一阶段迁移岗位管理作为字典与租户选择试点。
- 形成后续普通列表、树表、只读详情、主子表和用户管理的迁移顺序及验收清单。
- 验证浅色、深色、桌面和移动端布局。

### 3.3 范围外

- 用户管理、权限范围和 API 权限范围页面的正式迁移不属于第一阶段交付；在基础模式验证后进入后续批次。
- `src/page/` 中的 Avue 布局和导航组件暂不迁移。
- 工具示例页面是否保留或迁移由后续清理事项决定。
- 后端未公开支持的新增筛选条件不在前端迁移中擅自扩展。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：用户已登录，并拥有目标菜单及对应操作权限。
- 触发入口：系统管理或其他业务菜单中的已迁移页面。
- 最终结果：用户通过统一的搜索、列表和弹窗交互完成原有业务操作，业务数据及权限结果与迁移前一致。

1. 用户进入管理页面，系统按当前分页和默认查询条件加载列表。
2. 用户可以搜索、重置、切换页码、选择记录或发起新增、查看、编辑、删除等操作。
3. 前端执行输入校验并调用现有 API，后端继续执行认证、权限、租户和业务校验。
4. 成功后关闭弹窗、刷新列表并给出成功反馈；失败时保留可恢复的输入状态。
5. 未迁移页面继续使用现有 Avue 实现，不受迁移组件影响。

### 4.2 业务流程图

~~~mermaid
flowchart TD
    A([进入管理页面]) --> B{页面是否已迁移?}
    B -- 否 --> C[继续使用现有 Avue 页面]
    B -- 是 --> D[使用 Element Plus 页面加载列表]
    D --> E{加载成功?}
    E -- 否 --> F[统一错误提示并保留重试入口]
    F --> Z([结束])
    E -- 是 --> G[展示列表、分页和权限允许的操作]
    G --> H[用户查询或发起业务操作]
    H --> I{前置条件与表单校验通过?}
    I -- 否 --> J[提示原因且不提交请求]
    J --> G
    I -- 是 --> K[调用现有 SpringBlade API]
    K --> L{执行成功?}
    L -- 否 --> M[保留输入并恢复操作状态]
    M --> G
    L -- 是 --> N[刷新列表并显示成功反馈]
    N --> G
    C --> Z
~~~

### 4.3 异常与替代流程

| 编号 | 触发条件 | 系统行为 | 用户提示 | 数据是否改变 |
| --- | --- | --- | --- | :---: |
| EX-001 | 列表请求失败 | 结束加载状态，保留查询条件和当前页面 | 复用 Axios 统一错误提示，可重新查询或刷新 | 否 |
| EX-002 | 表单校验失败 | 不发送提交请求，定位无效字段 | 展示字段校验信息 | 否 |
| EX-003 | 新增或编辑请求失败 | 保持弹窗和用户输入，恢复提交按钮 | 复用统一错误提示 | 由后端事务决定，前端不假定成功 |
| EX-004 | 批量操作未选择记录 | 阻止请求 | 请选择至少一条数据 | 否 |
| EX-005 | 权限不足或登录失效 | 不展示无权限入口；服务端拒绝越权请求；401 进入现有退出登录流程 | 复用现有错误与登录反馈 | 否 |
| EX-006 | 后发请求先完成 | 只使用最近一次列表请求结果更新页面 | 无额外提示 | 否 |

## 5. 功能需求与验收标准

### 5.1 REQ-001 统一搜索面板

#### 5.1.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-004`
- 优先级：Must
- 触发入口：迁移页面顶部搜索区域。
- 前置条件：页面定义了查询模型和实际业务字段。
- 输入：查询字段、响应式列配置、加载状态。
- 处理规则：
  1. 页面通过插槽声明输入框、选择器、日期等业务字段。
  2. 面板根据当前容器宽度、查询字段列宽和操作区列宽自动计算首行容量；存在溢出字段时自动提供展开/收起操作。
  3. 查询和重置均将分页回到第一页。
  4. 收起附加条件时不得静默清空用户已填写内容。
- 输出：查询或重置事件，由页面加载列表。
- 限制：搜索面板不调用业务 API，不解释查询字段含义。

#### 5.1.2 验收标准

- `AC-001`：Given 页面存在基础查询字段，When 用户提交查询，Then 页面回到第一页并按当前条件加载一次列表。
- `AC-002`：Given 查询字段超过当前视口首行容量，When 面板完成布局或容器宽度变化，Then 自动显示展开/收起操作；用户切换状态时字段布局正确且已填值保持不变。
- `AC-003`：Given 列表正在加载，When 用户查看搜索区，Then 查询按钮显示加载状态且不会重复提交。
- `AC-004`：Given 用户点击重置，When 重置完成，Then 查询模型恢复初始值并重新加载第一页。

### 5.2 REQ-002 统一列表容器与分页

#### 5.2.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-004`
- 优先级：Must
- 触发入口：迁移页面列表区域。
- 前置条件：页面已准备列表数据、加载状态和分页状态。
- 输入：标题、页面自定义操作、`el-table` 内容、分页状态。
- 处理规则：
  1. 列表容器统一标题、工具栏、内容和底部区域布局。
  2. 页面直接声明 `el-table` 列、树表配置和业务插槽。
  3. 分页统一支持页码、每页数量和总数；改变每页数量时回到第一页。
  4. 移动端隐藏非必要分页信息，保留上一页、页码和下一页。
  5. 重要操作列在横向滚动时保持可访问。
- 输出：分页变化事件及页面自定义业务操作。
- 限制：列表容器不接收 API、权限码或声明式列 JSON。

#### 5.2.2 验收标准

- `AC-005`：Given 列表成功返回数据，When 页面渲染，Then 标题、工具栏、表格和分页布局一致且无重叠。
- `AC-006`：Given 用户切换页码，When 请求完成，Then 列表展示目标页数据且总数保持正确。
- `AC-007`：Given 用户改变每页数量，When 列表重新加载，Then 当前页为第一页且只发起一次有效加载。
- `AC-008`：Given 页面宽度小于 768px，When 查看列表，Then 分页可操作且操作列可访问。
- `AC-009`：Given 页面使用树表或懒加载表格，When 迁移，Then 页面可以直接使用 Element Plus 原生能力而无需绕过列表容器。

### 5.3 REQ-003 统一新增、编辑和查看弹窗

#### 5.3.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-004`
- 优先级：Must
- 触发入口：新增、查看、编辑按钮。
- 前置条件：用户拥有对应权限；页面提供表单模型、校验规则和提交函数。
- 输入：弹窗模式、实体名称、可见状态、提交状态和业务表单插槽。
- 处理规则：
  1. 弹窗支持新增、编辑、查看三种模式并生成一致标题。
  2. 查看模式不允许提交；新增和编辑必须先通过页面表单校验。
  3. 提交期间禁用重复提交和关闭冲突操作。
  4. 提交失败保留弹窗和输入；提交成功关闭弹窗并刷新列表。
- 输出：确认、取消和可见状态变更事件。
- 限制：弹窗不保存业务实体、不调用业务 API、不自动生成表单字段。

#### 5.3.2 验收标准

- `AC-010`：Given 用户打开新增弹窗，When 页面展示，Then 表单为初始值且标题、按钮符合新增模式。
- `AC-011`：Given 用户打开编辑或查看弹窗，When 详情加载完成，Then 再展示完整数据且多选字段转换正确。
- `AC-012`：Given 表单校验失败，When 用户提交，Then 不发送请求并显示字段错误。
- `AC-013`：Given 提交请求失败，When 请求结束，Then 弹窗保持打开、输入不丢失且提交按钮恢复。
- `AC-014`：Given 提交成功，When 请求结束，Then 弹窗关闭、列表刷新并显示成功反馈。

### 5.4 REQ-004 标准字典与远程选项

#### 5.4.1 需求说明

- 关联用户故事：`US-002`、`US-005`
- 优先级：Must
- 触发入口：表单选择字段和列表字典回显字段。
- 前置条件：字典编码或远程选项加载函数明确。
- 输入：字典编码、当前值、选择模式、禁用状态或业务加载函数。
- 处理规则：
  1. 标准 Blade 字典统一映射 `dictValue` 为标签、`dictKey` 为值。
  2. 同一页面重复使用同一字典时复用已加载数据，失败后允许重试。
  3. 租户、部门、角色、岗位和菜单树使用明确 API 加载，不解析动态 `dicUrl` 模板。
  4. 列表展示与表单选择使用相同值类型，避免字符串和数字隐式错配。
- 输出：选择值、字典标签或远程选项状态。
- 限制：通用字典组件不得接收任意 URL 并自行推断响应结构。

#### 5.4.2 验收标准

- `AC-015`：Given 有效字典编码，When 组件加载完成，Then 选择项和列表标签与后端字典一致。
- `AC-016`：Given 字典请求失败，When 页面展示，Then 不产生错误标签且用户可以重试加载。
- `AC-017`：Given 租户变化，When 页面重新加载部门、角色或岗位选项，Then 旧租户选项不会覆盖新租户结果。
- `AC-018`：Given 数字型字典值，When 编辑并提交，Then 值类型与后端契约一致。

### 5.5 REQ-005 分页、选择和权限状态复用

#### 5.5.1 需求说明

- 关联用户故事：`US-002`、`US-003`、`US-005`
- 优先级：Must
- 触发入口：迁移页面初始化及列表操作。
- 前置条件：页面提供符合实际响应结构的列表加载函数。
- 输入：查询初始值、分页加载函数、响应转换函数和权限模块名。
- 处理规则：
  1. 分页列表状态统一维护数据、查询、页码、总数和加载状态。
  2. 加载成功、预期失败和异常失败均必须结束加载状态。
  3. 只允许最近一次有效请求更新列表数据。
  4. 选择状态统一提供选中行、ID 集合和清空能力。
  5. 标准新增、查看、编辑、删除权限沿用 `{module}_{action}`；管理员专属操作由页面显式判断。
- 输出：页面可直接绑定的响应式状态与操作函数。
- 限制：树形非分页结果、主子表和特殊响应必须通过页面或专用转换明确适配。

#### 5.5.2 验收标准

- `AC-019`：Given 列表接口失败，When 请求结束，Then 加载状态恢复且原查询条件仍可再次使用。
- `AC-020`：Given 用户快速连续查询，When 多个请求乱序返回，Then 页面只展示最后一次查询结果。
- `AC-021`：Given 用户完成批量删除，When 操作成功，Then 选择状态清空且列表刷新。
- `AC-022`：Given 用户没有某操作权限，When 页面展示，Then 对应按钮不可见，且服务端仍负责最终授权。

### 5.6 REQ-006 渐进迁移与兼容

#### 5.6.1 需求说明

- 关联用户故事：`US-003`、`US-005`
- 优先级：Must
- 触发入口：每个页面进入迁移开发、评审和发布时。
- 前置条件：迁移页面已经建立迁移前功能清单。
- 输入：页面原有查询、列、表单、权限、字典、批量操作和特殊流程。
- 处理规则：
  1. 页面按独立批次迁移，路由、菜单地址和 API 保持不变。
  2. 未迁移页面继续使用 Avue，不因新增组件或样式发生变化。
  3. 每页迁移必须完成行为对照、类型检查、构建和浏览器验收。
  4. Avue 依赖仅在无运行时引用且专项清理验证通过后移除。
- 输出：已验证的 Element Plus 页面或保持原状的 Avue 页面。
- 限制：不得在单页迁移中顺带修改后端契约或无关全局样式。

#### 5.6.2 验收标准

- `AC-023`：Given 一个页面完成迁移，When 用户通过原菜单进入，Then 路由和业务入口不变。
- `AC-024`：Given 仍存在 Avue 页面，When 发布迁移页面，Then未迁移页面的查询、弹窗和表格不受影响。
- `AC-025`：Given 试点页面准备合并，When 执行工程验证，Then 类型检查和生产构建通过。
- `AC-026`：Given 迁移页面出现阻断性回归，When 回滚对应页面改动，Then 可恢复迁移前实现且不涉及数据恢复。

### 5.7 REQ-007 第一阶段试点

#### 5.7.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-003`
- 优先级：Must
- 触发入口：参数管理和岗位管理页面。
- 前置条件：REQ-001 至 REQ-006 的基础实现可用。
- 输入：现有参数、岗位页面行为和后端接口。
- 处理规则：

  2. 岗位管理验证租户选择、岗位类型字典、刷新和表单详情加载。
  3. 试点不增加新业务字段，不改变接口路径和权限码。
  4. 试点通过后才开始用户管理等复杂页面迁移。
- 输出：两个无 `avue-crud` 的 Element Plus 试点页面及迁移复盘结论。
- 限制：树表、主子表和用户导入不要求在第一阶段试点实现。

#### 5.7.2 验收标准

- `AC-029`：Given 试点页面在浅色、深色和移动端打开，When执行核心流程，Then 页面无内容重叠、文字溢出和不可访问操作。

### 5.8 REQ-008 Ant Design Vue 视觉与交互基线

#### 5.8.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-004`
- 优先级：Must
- 触发入口：所有新增通用组件和完成迁移的业务页面。
- 前置条件：页面已经明确业务字段、操作权限和响应式布局要求。
- 输入：Ant Design Vue 后台管理场景的搜索、列表、工具栏、弹窗、表单、标签和分页模式。
- 处理规则：
  1. 搜索区参考 Ant Design Vue Query Filter 的紧凑栅格、标签对齐、操作区右对齐和展开/收起方式。
  2. 列表区参考 Ant Design Vue ProTable 的标题、主操作、低频操作下沉、轻量表头、行分隔和分页层级。
  3. 新增、编辑、查看和详情参考 Ant Design Vue Modal/Drawer 的标题、正文、底部操作和提交反馈层级。
  4. 使用 8px 基础间距体系、克制圆角和清晰的信息层级，不使用营销式卡片、装饰渐变或大面积强调色。
  5. 主色、明暗主题和字体继续由 Saber/Element Plus Token 驱动，不硬编码 Ant Design 默认蓝色或复制 Ant Design Vue CSS。
  6. 图标使用项目已安装的 Element Plus Icons，以语义一致为准，不引入 Ant Design Icons。
- 输出：在视觉密度、操作层级和状态反馈上接近 Ant Design Vue，同时保持 Saber 主题能力的 Element Plus 页面。
- 限制：不得直接依赖 Ant Design Vue 组件、样式类、Less Token、DOM 结构或运行时代码。

#### 5.8.2 验收标准

- `AC-031`：Given 迁移页面在 1440px 视口展示，When 对照确认的 Ant Design Vue 管理页基准，Then 搜索、列表工具栏、表格、分页和弹窗的信息层级一致，无明显密度或对齐偏差。
- `AC-032`：Given 页面在 1024px 和 375px 视口展示，When 工具栏或表单发生换行，Then 操作顺序、间距和主要按钮层级保持清晰且无重叠。
- `AC-033`：Given 用户切换浅色、深色或自定义主色，When 页面重新渲染，Then 仍保持 Ant Design Vue 风格的信息层级，同时所有颜色来自 Saber/Element Plus Token。
- `AC-034`：Given 完成第一阶段构建，When 检查依赖、源码和产物，Then 不存在 Ant Design Vue、Ant Design Icons 或其样式包的运行时引用。
- `AC-035`：Given 页面进入评审，When 提交桌面、平板、移动端及明暗主题截图，Then 搜索、列表、弹窗、空状态、加载和失败状态均通过视觉评审。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 迁移不得改变 API 路径、请求方法、参数位置和响应解析语义 | 所有迁移页面 | 停止合并并修正 |
| BR-002 | 前端权限仅控制显示，服务端权限仍是安全边界 | 所有操作按钮 | 不允许以隐藏按钮替代后端授权 |
| BR-003 | 通用展示组件不得持有业务 API、权限码和实体转换 | 所有通用组件 | 逻辑移回页面或 composable |
| BR-004 | 页面直接使用 `el-table`，不得通过列 JSON 自动生成表格和表单 | 所有迁移页面 | 设计退回评审 |
| BR-005 | 迁移期不新增基础组件库和运行时依赖 | 整个项目 | 依赖变更必须单独立项 |
| BR-006 | 明暗主题使用现有 Saber CSS Token，不硬编码主题色 | 新增组件和页面 | 视觉验收不通过 |
| BR-007 | 请求错误由 `axios.ts` 统一提示，页面只恢复局部状态 | 所有 API 调用 | 移除重复普通错误提示 |
| BR-008 | 树表、主子表和特殊业务允许使用专用页面组件，不强求统一 CRUD 抽象 | 复杂页面 | 按专项设计实现 |
| BR-009 | 新组件和迁移页面必须仿照 Ant Design Vue 后台视觉与交互，但只使用 Element Plus 和 Saber Token 实现 | 所有新增组件和迁移页面 | 视觉评审不通过或依赖变更退回 |

### 6.2 页面迁移状态

| 状态 | 含义 | 允许操作 | 可迁移到 |
| --- | --- | --- | --- |
| `UNMIGRATED` | 页面仍完整使用现有 Avue 实现 | 功能维护、建立对照清单 | `PILOTING` |
| `PILOTING` | 页面正在 Element Plus 迁移和对照验证 | 开发、修正、回滚 | `VERIFIED`、`UNMIGRATED` |
| `VERIFIED` | 类型、构建和业务流程已验证 | 发布、观察 | `MIGRATED`、`UNMIGRATED` |
| `MIGRATED` | 页面正式使用 Element Plus 实现 | 正常维护 | 不适用 |

## 7. 认证与访问边界

### 7.1 资源归属

| 资源 | 归属类型 | 归属字段 | 字段来源 | 说明 |
| --- | --- | --- | --- | --- |
| 用户、岗位、参数等系统资源 | 租户级或平台级，以现有后端模型为准 | `tenant_id` 或现有实体字段 | 登录上下文与现有后端逻辑 | 前端迁移不改变归属规则 |
| 通用前端组件 | 不适用 | 无 | 不适用 | 不持久化业务数据 |

### 7.2 当前访问规则

| 操作 | 是否需要登录 | 业务前置条件 | 失败行为 |
| --- | :---: | --- | --- |
| 访问管理页面 | 是 | 拥有菜单访问权限 | 沿用现有路由守卫与后端认证 |
| 查询列表/详情 | 是 | 后端认证、租户和业务规则通过 | 401 退出登录；其他错误统一提示 |
| 新增、编辑、删除 | 是 | 对应 `{module}_{action}` 权限及后端校验通过 | 按现有接口错误处理，数据不假定改变 |
| 管理员专属操作 | 是 | `userInfo.authority` 包含 `admin` 且后端允许 | 隐藏入口，服务端最终拒绝越权请求 |

### 7.3 后续权限影响

- 权限资源：沿用现有 `permission` getter 中的模块权限。
- 权限动作：`add`、`view`、`edit`、`delete` 及页面已有自定义动作。
- 作用域：沿用现有租户、角色和数据权限设计。
- 当前处理：只迁移前端显示和交互，不新增权限表、权限码或授权模型。

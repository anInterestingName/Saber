## 2. 摘要与目标

### 2.1 摘要

第一阶段已经完成 Element Plus 通用搜索、列表、分页、表单弹窗、字典和 CRUD 状态能力的开发，
并通过参数管理、岗位管理验证了标准分页 CRUD 与租户/字典选择。本阶段将迁移普通 CRUD、报表入口和
只读日志等中等复杂度页面，验证第一阶段能力能否稳定覆盖更多业务类型，并补齐统一行操作和详情抽屉。

迁移保持现有菜单、权限、接口、租户、数据和业务操作不变。页面列表、搜索、分页和表单骨架不再使用
`avue-crud` 或 `avue-form`，但公告内容编辑仍须保留现有富文本能力，不得因组件迁移降级为纯文本。

### 2.2 需求目标

1. 将租户管理、客户端管理、数据源管理、通知公告、报表列表和三类日志页面迁移为 Element Plus 页面。
2. 复用第一阶段通用能力，并补齐普通页面需要的统一行操作和只读详情抽屉体验。
3. 保持标准 CRUD、批量删除、详情回填、公告富文本、报表设计/预览和日志查看行为不变。
4. 在更多模块中验证权限、敏感字段、长文本、外部页面和未迁移 Avue 页面兼容性。
5. 继续执行 Ant Design Vue 风格的信息密度和操作层级，但不引入新的前端基础组件库或运行时依赖。

| 指标 | 第二阶段基线 | 第二阶段目标值 | 统计口径 |
| --- | ---: | ---: | --- |
| 本阶段使用 `avue-crud` 的页面数 | 8 | 0 | 本文 3.2 节页面静态检索 |
| 累计纯 `el-table` 迁移页面数 | 2 | 至少 10 | 第一阶段 2 页加本阶段 8 页 |
| 新增前端运行时依赖 | 0 | 0 | `package.json` 与锁文件 |
| 本阶段页面类型检查通过率 | 不适用 | 100% | `pnpm run type-check` |
| 本阶段核心业务流程通过率 | 未建立 | 100% | 本文验收标准与业务验收记录 |
| 多视口、明暗主题视觉覆盖率 | 未建立 | 100% | 1440px、1024px、375px 及浅色/深色截图 |

### 2.3 非目标

- 本阶段不迁移字典、部门、菜单、角色、顶部菜单、用户和代码生成等树表或复杂单表页面。
- 本阶段不迁移数据权限、API 权限、区域和示例等主子表或专项页面。
- 本阶段不移除 Avue 包、全局 Avue 注册、Avue 主布局或未迁移页面的 Avue 用法。
- 本阶段不更换公告富文本产品能力，不建设新的通用富文本编辑器。
- 本阶段不建设上传组件；用户导入等上传场景留到后续复杂页面批次。
- 本阶段不改造报表设计器/预览服务，不改变报表服务地址、标识规则或页面能力。
- 本阶段不新增日志检索字段、日志删除、导出、统计或实时刷新能力。
- 本阶段不改变后端接口、数据库结构、认证头、Token、租户契约和权限码。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：用户已登录，拥有目标菜单和对应操作权限，相关后端服务可用。
- 触发入口：系统管理、工作台、开发工具、报表管理或监控管理中的目标菜单。
- 最终结果：用户通过统一 Element Plus 页面完成原有业务操作，或在失败时保留可恢复状态。

1. 用户进入目标页面，系统按默认分页和查询条件加载列表。
2. 用户执行查询、重置、分页或刷新，并按权限看到可用操作。
3. 标准 CRUD 页面执行表单校验和新增、查看、编辑、删除；报表页面打开设计/预览或删除；日志页面加载只读详情。
4. 成功后刷新必要状态并给出反馈；失败时恢复按钮和加载状态，不伪造成功结果。
5. 未迁移页面继续按现有 Avue 行为运行。

### 4.2 业务流程图

~~~mermaid
flowchart TD
    A([进入第二阶段目标页面]) --> B[加载列表、分页和权限状态]
    B --> C{列表加载成功?}
    C -- 否 --> D[结束加载并保留重试入口]
    D --> Z([结束])
    C -- 是 --> E[展示搜索、列表和允许的操作]
    E --> F{用户操作类型}
    F -- 查询/分页 --> G[按当前条件重新加载]
    G --> C
    F -- 新增/编辑/删除 --> H[校验权限、选择和表单]
    H --> I{校验通过?}
    I -- 否 --> J[提示原因且不发业务请求]
    J --> E
    I -- 是 --> K[调用现有业务接口]
    K --> L{执行成功?}
    L -- 否 --> M[保留可恢复状态]
    M --> E
    L -- 是 --> N[刷新列表并反馈成功]
    N --> E
    F -- 报表设计/预览 --> O[按现有标识打开报表服务页面]
    O --> E
    F -- 查看日志 --> P[加载并展示只读详情]
    P --> E
~~~

### 4.3 异常与替代流程

| 编号 | 触发条件 | 系统行为 | 用户提示 | 数据是否改变 |
| --- | --- | --- | --- | :---: |
| EX-001 | 列表请求失败 | 结束加载，保留查询条件和再次加载能力 | 复用 Axios 统一错误提示 | 否 |
| EX-002 | 详情请求失败 | 不展示旧记录详情，结束详情加载并允许关闭/重试 | 复用统一错误提示 | 否 |
| EX-003 | 表单校验失败 | 定位无效字段，不发请求 | 展示字段校验信息 | 否 |
| EX-004 | 保存请求失败 | 保持弹窗和输入，恢复提交按钮 | 复用统一错误提示 | 由后端事务决定 |
| EX-005 | 删除时未选择记录 | 阻止批量删除请求 | 请选择至少一条数据 | 否 |
| EX-006 | 删除失败 | 保留当前选择，允许重新确认 | 复用统一错误提示 | 由后端事务决定 |
| EX-007 | 报表服务地址不可用或浏览器阻止新窗口 | 当前列表保持可用，不产生本地成功状态 | 允许用户再次发起操作 | 否 |
| EX-008 | 日志详情包含超长参数或堆栈 | 在详情区换行或滚动，不撑破页面 | 无额外提示 | 否 |
| EX-009 | 权限不足或登录失效 | 隐藏无权限入口；服务端仍执行最终授权；401 沿用退出流程 | 复用现有权限和登录反馈 | 否 |
| EX-010 | 快速连续查询导致响应乱序 | 仅最后一次有效请求更新页面 | 无额外提示 | 否 |

## 5. 功能需求与验收标准

### 5.1 REQ-001 统一普通列表与行操作

#### 5.1.1 需求说明

- 关联用户故事：`US-006`、`US-007`
- 优先级：Must
- 触发入口：本阶段全部目标页面。
- 前置条件：第一阶段通用搜索、列表、分页和状态能力可用。
- 输入：页面查询字段、列表数据、分页状态、权限状态和页面专属操作。
- 处理规则：
  1. 页面统一展示搜索区、列表标题、主操作、低频操作、表格、行操作和分页。
  2. 查看、编辑、删除等标准行操作保持顺序和视觉层级一致，页面可以追加设计、预览等专属操作。
  3. 无权限操作不可见；加载或提交期间阻止重复操作。
  4. 搜索、重置和改变每页数量均按既定规则回到第一页，刷新保留当前有效查询。
  5. 横向空间不足时优先保证主操作和行操作可访问，不允许工具栏与表格内容重叠。
- 输出：一致且可复用的列表与行操作体验。
- 限制：不得通过声明式列配置重新建设 CRUD 引擎。

#### 5.1.2 验收标准

- `AC-001`：Given 任一本阶段页面加载成功，When 用户查看页面，Then 搜索、工具栏、表格、行操作和分页层级一致且无重叠。
- `AC-002`：Given 用户没有某项按钮权限，When 页面展示，Then 对应操作不可见，且服务端仍负责最终授权。
- `AC-003`：Given 用户提交查询或重置，When 请求发起，Then 页码回到第一页且只产生一次有效列表加载。
- `AC-004`：Given 用户快速连续改变查询或分页，When 响应乱序返回，Then 只显示最后一次有效结果。
- `AC-005`：Given 页面宽度为 375px，When 工具栏或操作列空间不足，Then 主要操作仍可访问且文字不溢出。

### 5.2 REQ-002 租户、客户端和数据源管理

#### 5.2.1 需求说明

- 关联用户故事：`US-001`、`US-002`
- 优先级：Must
- 触发入口：租户管理、客户端管理、数据源管理。
- 前置条件：用户拥有页面及对应新增、查看、编辑或删除权限。
- 输入：现有查询条件、分页、表单字段、选择项和操作权限。
- 处理规则：
  1. 租户管理保留按租户 ID、租户名称和联系人查询，以及单条/批量 CRUD；租户 ID 不在新增和编辑时由用户修改。
  2. 客户端管理保留客户端 ID、密钥查询、详情加载、单条/批量 CRUD 和全部授权配置字段。
  3. 新增客户端保留授权类型、授权范围、访问令牌秒数和刷新令牌秒数的现有默认值。
  4. 数据源管理保留 MySQL、PostgreSQL、Oracle 驱动选项，以及名称、用户名、密码、连接地址和备注。
  5. 编辑和查看客户端、数据源时先加载目标记录详情，再展示完整且属于当前记录的数据。
  6. 保存失败保留输入；删除成功刷新列表并清空选择，删除失败保留选择。
- 输出：与迁移前一致的租户、客户端和数据源维护结果。
- 限制：不得新增查询字段、连接测试、密钥管理或后端校验规则。

#### 5.2.2 验收标准

- `AC-006`：Given 用户进入租户管理，When 查询、重置和切换分页，Then 列表条件、页码和总数正确。
- `AC-007`：Given 用户新增、查看或编辑租户，When 打开表单，Then 字段可见性和必填校验与现有业务一致，租户 ID 不可在新增/编辑中修改。
- `AC-008`：Given 用户新增客户端，When 表单打开，Then 现有授权类型、范围和令牌时长默认值准确回填。
- `AC-009`：Given 用户查看或编辑客户端，When 详情加载完成，Then 全部授权字段属于目标记录且提交值类型不变。
- `AC-010`：Given 用户新增或编辑数据源，When 选择驱动并提交，Then 驱动、连接信息和备注按现有契约保存。
- `AC-011`：Given 客户端或数据源详情加载失败，When 请求结束，Then 不展示上一条记录内容且不能误提交旧数据。
- `AC-012`：Given 用户执行单删或批量删除，When 操作成功，Then 列表刷新且选择清空；When 操作失败，Then 选择仍可用于重试。

### 5.3 REQ-003 通知公告管理

#### 5.3.1 需求说明

- 关联用户故事：`US-003`
- 优先级：Must
- 触发入口：通知公告页面。
- 前置条件：用户拥有对应按钮权限；通知类型字典可用。
- 输入：通知标题、通知类型、通知日期和通知内容。
- 处理规则：
  1. 保留按通知标题和通知类型查询、分页、查看、新增、编辑、单删和批量删除。
  2. 通知类型继续使用 `notice` 字典，列表标签和表单值保持相同后端值类型。
  3. 通知日期继续按 `YYYY-MM-DD HH:mm:ss` 语义展示和提交。
  4. 通知内容必须保留现有富文本编辑、详情回填和只读展示能力，不得降级为纯文本输入。
  5. 编辑和查看前加载详情；失败时不得显示上一条公告内容。
- 输出：与迁移前内容和格式一致的公告记录。
- 限制：不新增发布状态、受众、附件或定时任务。

#### 5.3.2 验收标准

- `AC-013`：Given 通知类型字典加载成功，When 用户查询或编辑公告，Then 类型标签、选项、回显和提交值一致。
- `AC-014`：Given 用户新增或编辑公告，When 输入带格式内容并保存后再次查看，Then 标题、时间和富文本格式完整保留。
- `AC-015`：Given 公告必填字段缺失，When 用户提交，Then 不发送请求并显示对应字段错误。
- `AC-016`：Given 公告详情或保存请求失败，When 请求结束，Then 不显示旧详情，或保留当前未保存输入以便重试。
- `AC-017`：Given 用户完成单删或批量删除，When 后端返回成功，Then 列表和选择状态同步更新。

### 5.4 REQ-004 报表列表专项操作

#### 5.4.1 需求说明

- 关联用户故事：`US-004`
- 优先级：Must
- 触发入口：报表列表页面的文件名、设计、预览和删除操作。
- 前置条件：报表服务地址已配置，用户拥有现有菜单及服务端访问条件。
- 输入：报表文件名、分页查询和选中记录。
- 处理规则：
  1. 保留按文件名查询、分页、刷新、单删和批量删除。
  2. 点击文件名或预览操作继续打开对应报表预览页。
  3. 点击设计操作继续打开对应报表设计器。
  4. 报表服务地址和报表标识拼装语义保持不变，不由迁移页面缓存或解释报表内容。
  5. 新窗口打开失败不得影响当前列表状态，也不得显示虚假成功反馈。
- 输出：报表服务页面或更新后的报表列表。
- 限制：不改变外部报表产品，不新增报表文件编辑 API。

#### 5.4.2 验收标准

- `AC-018`：Given 报表服务配置有效，When 用户点击文件名或预览，Then 新窗口打开目标报表预览页且当前列表保持不变。
- `AC-019`：Given 报表服务配置有效，When 用户点击设计，Then 新窗口打开目标报表设计器并使用正确报表标识。
- `AC-020`：Given 用户按文件名查询，When 请求完成，Then 列表、总数和分页与后端结果一致。
- `AC-021`：Given 用户未选择记录，When 点击批量删除，Then 不发送请求并提示选择数据。
- `AC-022`：Given 删除成功或失败，When 请求结束，Then 成功时刷新并清空选择，失败时保留选择和当前查询。

### 5.5 REQ-005 通用、接口和错误日志详情

#### 5.5.1 需求说明

- 关联用户故事：`US-005`
- 优先级：Must
- 触发入口：通用日志、接口日志和错误日志页面。
- 前置条件：用户拥有对应 `log_usual_view`、`log_api_view` 或 `log_error_view` 权限。
- 输入：服务 ID、服务 Host、分页状态和目标日志 ID。
- 处理规则：
  1. 三类日志均保留按服务 ID、服务 Host 查询和分页能力。
  2. 列表保留各自服务、环境、接口、级别/标题、方法和时间等现有字段。
  3. 查看操作先加载目标日志详情，再在统一只读抽屉中展示。
  4. 用户代理、请求数据和错误堆栈等长文本保持原始内容并支持换行或区域滚动。
  5. 日志页面只读，不展示新增、编辑、删除或提交操作。
  6. 关闭详情后清理当前详情状态，下一次打开不得闪现上一条日志。
- 输出：可扫描的日志列表和完整只读详情。
- 限制：不修改日志内容，不增加复制、下载、删除、聚合或实时流能力。

#### 5.5.2 验收标准

- `AC-023`：Given 用户查询任一日志类型，When 输入服务 ID 或 Host，Then 页码回到第一页并展示匹配结果。
- `AC-024`：Given 用户具有对应查看权限，When 打开日志详情，Then 抽屉展示目标记录全部现有详情字段且无编辑入口。
- `AC-025`：Given 用户不具有对应查看权限，When 页面展示，Then 查看入口不可见。
- `AC-026`：Given 请求参数或错误堆栈为超长文本，When 详情展示，Then 内容可完整读取且不撑破抽屉或页面。
- `AC-027`：Given 日志详情加载失败或连续切换记录，When 请求完成，Then 不显示旧记录或错配记录。
- `AC-028`：Given 用户关闭详情抽屉，When 再打开其他记录，Then 页面只展示新记录加载态和详情。

### 5.6 REQ-006 渐进迁移、兼容与回滚

#### 5.6.2 验收标准

- `AC-031`：Given 第一阶段参数、岗位页面，When 第二阶段通用组件调整完成，Then 两页核心流程和布局无回归。
- `AC-032`：Given 代表性未迁移 Avue 页面，When 发布前执行冒烟，Then 查询、表格和弹窗仍可正常使用。
- `AC-033`：Given 任一页面发生阻断性回归，When 回滚该页面改动，Then 可恢复迁移前实现且不需要数据恢复。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 迁移不得改变现有 API 路径、方法、参数位置、响应解析和报表标识语义 | 所有目标页面 | 停止合并并修正 |
| BR-002 | 页面按钮权限只控制入口显示，服务端授权仍是安全边界 | CRUD、日志查看、报表操作 | 不允许以隐藏按钮替代服务端校验 |
| BR-003 | 客户端密钥、数据源密码、Token 和日志敏感内容不得写入控制台或本地持久化 | 客户端、数据源、日志 | 安全验收不通过 |
| BR-004 | 迁移不得扩大敏感字段的可见范围；具体脱敏和编辑回填语义以现有后端契约及评审结论为准 | 客户端、数据源、日志 | 停止相关页面验收 |
| BR-005 | 公告类型使用 `notice` 字典，值类型和时间格式不得因组件替换发生隐式转换 | 通知公告 | 阻止提交并修正 |
| BR-006 | 公告内容必须保留富文本语义，不得在读取、编辑或提交中丢失格式 | 通知公告 | 业务验收不通过 |
| BR-007 | 报表设计与预览使用现有报表服务和 `blade-{name}` 标识语义 | 报表列表 | 不打开错误报表 |
| BR-008 | 三类日志为只读资源，前端不得提供写操作 | 日志页面 | 移除写入口 |
| BR-009 | 删除成功后清空选择，删除失败时保留选择；空选择不得发请求 | 可删除页面 | 恢复正确状态后重试 |
| BR-010 | 迁移页面不得保留 `avue-crud`/`avue-form`，也不得重新实现声明式 CRUD 引擎 | 本阶段 8 个页面 | 设计退回评审 |
| BR-011 | 页面样式使用现有 Token，且不得影响第一阶段和未迁移页面 | 全部前端改动 | 兼容性验收不通过 |

### 6.2 页面迁移状态

| 状态 | 含义 | 允许操作 | 可迁移到 |
| --- | --- | --- | --- |
| `UNMIGRATED` | 页面仍使用现有 Avue 实现 | 建立对照清单、修复原有阻断问题 | `PILOTING` |
| `PILOTING` | 页面正在迁移和对照验证 | 开发、验证、修正、回滚 | `VERIFIED`、`UNMIGRATED` |
| `VERIFIED` | 页面已通过工程与核心业务验证 | 发布、观察 | `MIGRATED`、`UNMIGRATED` |
| `MIGRATED` | 页面正式使用 Element Plus 实现 | 正常维护 | 不适用 |

只有目标页面的全部 Must 验收标准完成并留下验证证据后，才可从 `VERIFIED` 进入 `MIGRATED`。

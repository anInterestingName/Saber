## 2. 摘要与目标

### 2.1 摘要

前三阶段已经建设 Element Plus 通用能力，并完成标准 CRUD、只读列表、树表、授权、用户和代码生成等页面的
迁移开发。第三阶段明确将数据权限、API 权限、行政区划以及 `src/views/util/` 中仍依赖
`avue-crud`、`avue-form` 的示例页面移交第四阶段。

第四阶段迁移数据权限、API 权限和行政区划 3 个生产页面，并对表格、表单、权限控制 3 个示例页面完成保留替换
或下线处置。重点不是继续扩展通用 CRUD，而是处理“懒加载菜单主表 + 权限规则子表”、行政区划懒加载树与级联
调试，以及页面层 `avue-crud`、`avue-form` 使用点的收尾。

迁移保持现有菜单入口、后端接口、数据结构、角色授权引用、区划编码、认证方式和业务结果不变。数据权限和 API
权限是运行时访问控制配置，任何迁移结果都不得因界面默认值、异步串用或错误绑定而扩大用户可见数据或接口访问
范围。

术语说明：本文“第四阶段”仅指 [REQ-2026-001](REQ-2026-001-element-plus-migration.md) 路线图中的
Element Plus 页面迁移第四批次，不是 `doc/guide/Saber-5.0迁移升级指南.md` 中“构建配置层 TS 化”的
第四阶段。

### 2.2 需求目标

1. 将数据权限、API 权限和行政区划 3 个生产页面迁移为纯 Element Plus 页面。
2. 对表格、表单和权限控制 3 个示例页面形成明确处置结论，并消除其 `avue-crud`、`avue-form` 使用。
3. 保持菜单懒加载、权限规则 CRUD、角色授权引用、区划维护和三级区划调试行为不变。
4. 隔离菜单查询、权限子表查询、当前菜单、详情和提交状态，防止跨菜单或乱序响应污染权限配置。
5. 完成 `src/views/` 页面层 `avue-crud`、`avue-form` 使用点收尾，同时维持其他 Avue 能力的兼容边界。
6. 延续前三阶段的权限、主题、响应式、类型检查、生产构建和跨阶段回归门禁。

| 指标 | 第四阶段基线 | 第四阶段目标值 | 统计口径 |
| --- | ---: | ---: | --- |
| 使用 `avue-crud` 的 `src/views` 页面数 | 4 | 0 | datascope、apiscope、util/table、util/permission 静态检索 |
| 使用 `avue-form` 的 `src/views` 页面数 | 2 | 0 | region、util/form 静态检索 |
| 本阶段生产迁移页面数 | 0 | 3 | datascope、apiscope、region |
| 本阶段示例页面处置数 | 0 | 3 | util/table、util/form、util/permission |
| 新增运行时依赖 | 0 | 0 | `package.json` 与 `pnpm-lock.yaml` |
| 本阶段页面类型检查通过率 | 不适用 | 100% | `pnpm run type-check` |
| Must 验收标准通过率 | 未建立 | 100% | 本文 AC 与正式验收记录 |
| 多视口、明暗主题视觉覆盖率 | 未建立 | 100% | 1440px、1024px、375px 及浅色/深色截图 |

### 2.3 非目标

- 本阶段不移除 `@smallwei/avue` 依赖、全局 Avue 注册或 `src/page/` 中的 Avue 主布局能力。
- 本阶段不迁移 `avue-ueditor`、`avue-data-pay` 等不属于 `avue-crud`、`avue-form` 收尾范围的专项组件。
- 本阶段不改造工作台首页、可视化大屏或发布说明中的普通文本引用。
- 本阶段不重新迁移第三阶段菜单管理页面，也不在权限范围页新增第二个菜单维护入口。
- 本阶段不改变数据权限规则类型、规则表达式语法、Mapper 类名语义或服务端 SQL 拼接机制。
- 本阶段不改变 API 权限路径匹配算法、角色授权模型、权限缓存策略或新增权限审批、审计能力。
- 本阶段不修改行政区划编码体系、层级上限、数据源、后端级联关系或批量导入能力。
- 本阶段不把工具示例页建设为新的低代码平台、组件文档站或可持久化业务模块。
- 本阶段不修改数据库结构、后端接口路径、认证头、Token Cookie Key、多租户契约或既有权限码。

## 4. 业务流程

### 4.1 流程说明

- 前置条件：用户已登录并拥有目标菜单和现有操作资格；系统、字典、菜单和权限服务可用。
- 开发准入：REQ-2026-003 的 Must 验收与工程门禁通过，或评审形成明确的带风险准入结论。
- 触发入口：权限管理、基础管理或工具示例中的目标菜单。
- 最终结果：权限规则或行政区划按现有契约保存，示例页完成明确处置；失败时不显示虚假成功，也不污染其他菜单、记录或层级。

1. 用户进入目标页面，系统加载菜单根节点、行政区划根节点或本地示例数据。
2. 用户查询、展开节点或选择区划，系统只使用当前页面上下文展示对应结果。
3. 用户在数据/API 权限页打开某菜单的配置抽屉，系统清空旧菜单状态并加载该菜单的权限规则。
4. 用户查询、查看、新增、编辑或删除规则，系统绑定当前菜单并按现有字典、字段和接口契约提交。
5. 用户在行政区划页查看详情、新增下级、编辑、删除或执行省市区级联调试。
6. 成功后刷新受影响的子表、树分支或详情并反馈；失败时保留可重试上下文且不扩大权限范围。
7. 工具示例页按评审结论替换为 Element Plus 或从可访问入口下线，不再使用 Avue CRUD/Form。

## 5. 功能需求与验收标准

### 5.1 REQ-001 第四阶段范围基线与收尾边界

#### 5.1.1 需求说明

- 关联用户故事：`US-005`、`US-006`
- 优先级：Must
- 触发入口：第四阶段需求评审、开发准入和发布验收。
- 前置条件：第三阶段交付范围和当前 `src/views` 使用点已经完成静态核查。
- 输入：6 个目标页、当前菜单引用、Avue 使用清单和前三阶段验收状态。
- 处理规则：
  1. 生产范围固定为 datascope、apiscope、region，示例处置范围固定为 table、form、permission。
  2. 目标页完成后不得再包含 `avue-crud` 或 `avue-form`；不得通过别名、动态组件或二次封装保留同类依赖。
  3. 示例页开发前必须核查动态菜单、文档和源码引用；未获下线确认时默认原路径保留并替换为 Element Plus。
  4. `avue-tree`、`avue-ueditor`、`avue-data-pay` 和主布局属于独立迁移边界，不能据此移除 Avue 依赖。
  5. 每个生产页面建立迁移前后的字段、操作、权限、接口、字典和失败行为对照清单。
- 输出：范围明确、可逐页回滚且不误删 Avue 运行时的第四阶段交付。
- 限制：示例页下线属于外部可见入口变化，必须经产品和菜单负责人确认。

#### 5.1.2 验收标准

- `AC-001`：Given 检查 6 个目标页，When 静态检索，Then 不包含 `avue-crud` 或 `avue-form`。
- `AC-002`：Given 检查全部 `src/views`，When 静态检索，Then `avue-crud`、`avue-form` 页面使用数均为 0。
- `AC-003`：Given 仓库仍有其他 Avue 组件使用，When 检查依赖与全局注册，Then 未被本阶段错误移除。
- `AC-004`：Given 任一示例页准备下线，When 查看评审记录，Then 存在菜单、文档和源码引用核查及批准结论。
- `AC-005`：Given 示例页没有明确下线结论，When 第四阶段交付，Then 原路径仍可访问且使用 Element Plus 展示。
- `AC-006`：Given 任一生产页准备开发，When 进入实现，Then 已建立迁移前后的业务对照清单。

### 5.2 REQ-002 权限范围页的菜单主表与抽屉上下文

#### 5.2.1 需求说明

- 关联用户故事：`US-001`、`US-002`、`US-006`
- 优先级：Must
- 触发入口：数据权限和 API 权限页面。
- 前置条件：用户能够访问页面；菜单懒加载接口可用。
- 输入：菜单名称、菜单编号、父节点、当前菜单和权限规则查询条件。
- 处理规则：
  1. 页面按现有菜单接口加载根节点和子节点，使用稳定菜单 ID 识别节点和权限归属。
  2. 菜单侧保留名称、编号查询、重置、刷新和懒加载；搜索结果不得错误拼接到旧树节点。
  3. 本页面只承担选择菜单并进入权限配置，不新增菜单维护能力；菜单维护继续由第三阶段菜单管理页负责。
  4. 打开抽屉时记录菜单 ID、名称；数据权限页同时记录菜单编号用于规则默认值。
  5. 每次切换菜单前清空旧规则列表、查询、分页、选择、详情和提交状态，再加载当前菜单第一页。
  6. 菜单查询与权限子表查询完全隔离，分页和刷新只能使用各自最后一次已执行条件。
  7. 抽屉标题明确展示当前菜单；关闭后不得在后台继续用旧菜单响应覆盖下一次打开结果。
- 输出：上下文清晰且不会跨菜单串用数据的主表与抽屉页面。
- 限制：不改变 `getLazyMenuList` 及权限规则接口的请求和响应契约。

#### 5.2.2 验收标准

- `AC-007`：Given 页面初次打开，When 菜单根节点和子节点加载，Then 层级、叶子状态和菜单 ID 与后端一致。
- `AC-008`：Given 用户查询或重置菜单，When 请求完成，Then 页面只展示当前条件结果且可继续展开有效节点。
- `AC-009`：Given 用户打开某菜单配置，When 抽屉显示，Then 标题和所有规则请求均绑定该菜单 ID。
- `AC-010`：Given 用户从菜单 A 快速切换到菜单 B，When A 的请求晚于 B 返回，Then 抽屉只展示菜单 B 的数据。
- `AC-011`：Given 用户在规则子表执行查询后翻页或刷新，When 请求发出，Then 不携带菜单侧查询条件且保留子表条件。
- `AC-012`：Given 用户关闭抽屉后重新打开其他菜单，When 新数据加载，Then 不残留旧分页、选择、表单或提交状态。

### 5.3 REQ-003 数据权限规则维护

#### 5.3.1 需求说明

- 关联用户故事：`US-001`、`US-006`
- 优先级：Must
- 触发入口：数据权限页某菜单行的“权限配置”。
- 前置条件：用户满足现有管理员要求和 `data_scope_setting` 入口控制；当前菜单有效。
- 输入：权限名称、资源编号、权限字段、规则类型、可见字段、权限类名、规则值和备注。
- 处理规则：
  1. 规则列表始终按当前 `menuId` 分页，支持权限名称、资源编号查询及单条、批量删除。
  2. 新增规则默认绑定当前菜单；资源编号默认取当前菜单编号；可见字段默认值保持 `*`。
  3. `data_scope_type` 保持数字值：1 全部可见、2 本人可见、3 所在机构可见、4 所在机构及子级可见、5 自定义。
  4. 新增时按规则类型回填默认名称和权限字段：1 对应 `-`，2 对应 `create_user`，3、4 对应 `create_dept`，5 由用户明确填写。
  5. 仅自定义规则显示规则值；规则值是否必填及允许格式必须在需求确认前与后端契约对齐。
  6. 切换到非自定义类型时，不得把不可见的旧自定义值误提交为当前规则。
  7. 权限名称、资源编号、权限字段、规则类型、可见字段和权限类名沿用当前必填行为，实际校验以现有后端实体契约为上限。
  8. 查看或编辑必须先加载目标详情；编辑已有规则时不得被新增默认值覆盖。
  9. 保存、删除成功后刷新当前菜单当前查询的规则列表并清空相关选择；失败时保留上下文。
  10. 权限变更不得由前端推断已对所有会话即时生效；验收需结合后端缓存和角色授权结果确认。
- 输出：与当前菜单正确绑定、类型和值一致的数据权限规则。
- 限制：不验证或改写自定义规则表达式语法，不承诺服务端 SQL 副作用可由前端回滚。

#### 5.3.2 验收标准

- `AC-013`：Given 菜单存在多条数据规则，When 打开抽屉并分页查询，Then 总数、记录和查询条件均只属于当前菜单。
- `AC-014`：Given 用户新增非自定义规则，When 选择类型 1 至 4，Then 名称、资源编号和权限字段按规则回填且值类型正确。
- `AC-015`：Given 用户新增自定义规则，When 选择类型 5，Then 权限字段与规则值可编辑，空值和格式按已确认契约校验。
- `AC-016`：Given 用户从自定义类型切换到非自定义类型，When 提交，Then 不携带会改变当前规则语义的陈旧自定义值。
- `AC-017`：Given 用户查看或编辑既有规则，When 详情加载完成，Then 所有字段按服务端值回填且不被新增默认值覆盖。
- `AC-018`：Given 用户新增或编辑规则，When 提交，Then 请求携带当前菜单 ID，成功后刷新当前规则列表。
- `AC-019`：Given 用户未选择规则，When 执行批量删除，Then 请求被阻止；选择一条或多条后经确认可提交对应 ID 集合。
- `AC-020`：Given 保存、详情或删除请求失败，When 请求结束，Then 表单、列表和选择处于可重试状态且不显示成功。
- `AC-021`：Given 数据权限规则已变更，When 使用关联角色验证受控数据，Then 结果与确认的规则和角色授权一致，无权限扩大。

### 5.4 REQ-004 API 权限规则维护

#### 5.4.1 需求说明

- 关联用户故事：`US-002`、`US-006`
- 优先级：Must
- 触发入口：API 权限页某菜单行的“权限配置”。
- 前置条件：用户满足现有管理员要求和 `api_scope_setting` 入口控制；当前菜单有效。
- 输入：权限名称、资源编号、权限路径、接口类型和备注。
- 处理规则：
  1. 规则列表始终按当前 `menuId` 分页，支持权限名称、资源编号查询及单条、批量删除。
  2. 新增和编辑必须绑定当前菜单，不得沿用上一次打开菜单的 `menuId`。
  3. `api_scope_type` 保持数字值：1 系统接口、2 业务接口；列表标签和表单选项使用同一字典映射。
  4. 权限名称、资源编号、权限路径和接口类型为必填；权限路径原值和匹配语义保持不变。
  5. 查看或编辑必须先加载目标详情；失败时不得展示或提交上一条规则数据。
  6. 保存、删除成功后刷新当前菜单当前查询的规则列表并清空相关选择；失败时保留上下文。
  7. API 权限直接影响服务端访问判断，页面不得通过自动补全、格式化或路径归一化改变历史值。
  8. 权限变更后的实际命中结果必须使用受控角色和明确接口验证，不能只根据保存接口成功判定通过。
- 输出：与当前菜单正确绑定且不改变匹配语义的 API 权限规则。
- 限制：不改变服务端当前路径包含匹配算法，不在前端承诺路径冲突检测能力。

#### 5.4.2 验收标准

- `AC-022`：Given 菜单存在多条 API 规则，When 打开抽屉并分页查询，Then 总数、记录和条件均只属于当前菜单。
- `AC-023`：Given 用户新增 API 规则，When 选择系统接口或业务接口，Then 提交数字类型 1 或 2 且标签正确。
- `AC-024`：Given 权限名称、资源编号、权限路径或接口类型缺失，When 提交，Then 不发送保存请求并定位错误字段。
- `AC-025`：Given 用户查看或编辑既有规则，When 详情加载完成，Then 路径保持服务端原值且菜单绑定不变。
- `AC-026`：Given 用户从菜单 A 切换到菜单 B 后新增规则，When 提交，Then 请求只携带菜单 B 的 ID。
- `AC-027`：Given 保存、详情或删除请求失败，When 请求结束，Then 页面保留可重试上下文且不显示成功。
- `AC-028`：Given 用户完成单条或批量删除，When 请求成功，Then 当前列表刷新、选择清空且其他菜单规则不受影响。
- `AC-029`：Given API 权限规则已变更，When 使用关联角色访问目标与非目标接口，Then 结果符合确认的规则且无访问范围扩大。

### 5.5 REQ-005 行政区划维护与级联调试

#### 5.5.1 需求说明

- 关联用户故事：`US-003`、`US-004`、`US-006`
- 优先级：Must
- 触发入口：行政区划页面。
- 前置条件：用户拥有现有页面访问及 `region_add`、`region_delete`、`region_debug` 对应操作资格。
- 输入：当前区划、父区划、子编号、名称、等级、排序、备注和省市区调试选项。
- 处理规则：
  1. 区划树从根编码 `00` 开始懒加载，按后端 `hasChildren` 判断是否可展开，不能把加载失败视为叶子节点。
  2. 点击节点后按区划编码加载详情；快速切换时仅最后选择节点可回填表单。
  3. 新增下级必须基于已选择节点，父区划编号和名称取当前节点，完整编码由父编号与子编号按现有契约拼接；根编号 `00` 仅表示根上下文，不作为下级完整编码前缀。
  4. 新增下级等级在当前等级基础上递增，最大保持 5；用户仍需看到并确认最终等级。
  5. 区划编号、名称、等级和排序为必填；父区划字段只读，不允许通过表单把节点移动到其他父级。
  6. 编辑沿用当前详情和 `/submit` 契约；是否允许修改主键编码必须在详细设计前与后端确认。
  7. 删除必须基于当前已确认节点并二次确认；删除约束和子级处理以服务端结果为准。
  8. 保存或删除成功后刷新受影响树并清空无效选择；失败时保留当前节点、表单和可重试状态。
  9. 调试弹窗保留省、市、区三级联动；切换上级后清空并重新加载全部下级值，不能显示旧级联数据。
  10. `region` 字典保持 0 至 5 的数字层级值，不改变国家、省份/直辖市、地市、区县、乡镇、村委语义。
- 输出：层级、编码和详情一致的行政区划树，以及可观察的省市区级联调试结果。
- 限制：不新增节点移动、批量编辑、外部数据同步或删除级联策略。

#### 5.5.2 验收标准

- `AC-030`：Given 行政区划页打开，When 根节点和多级子节点加载，Then 编码、名称、层级和叶子状态与后端一致。
- `AC-031`：Given 用户快速点击两个区划节点，When 详情乱序返回，Then 表单只展示最后选择节点的详情。
- `AC-032`：Given 用户未选择有效节点，When 点击新增下级或删除，Then 不发送请求并提示先选择区划。
- `AC-033`：Given 用户对某节点新增下级，When 表单初始化，Then 父编号、父名称、完整编码和等级按规则生成。
- `AC-034`：Given 当前节点等级为 5，When 新增下级，Then 页面不会生成超过 5 的等级值。
- `AC-035`：Given 必填字段或子编号不符合确认规则，When 提交，Then 不发送请求并显示字段级错误。
- `AC-036`：Given 保存或删除成功，When 页面刷新，Then 受影响节点结果与服务端一致且无陈旧详情。
- `AC-037`：Given 保存或删除失败，When 请求结束，Then 树和表单不显示未确认结果且可以重试。
- `AC-038`：Given 用户在调试弹窗依次选择省、市、区，When 任一级变化，Then 下级选项和值同步清空并按当前上级重新加载。

- `AC-054`：Given 任一生产页出现阻断回归，When 回滚该页面，Then 原入口恢复且其他已迁移页面无需同步回滚。

## 6. 业务规则与状态

### 6.1 业务规则

| 规则编号 | 规则 | 适用范围 | 违反时行为 |
| --- | --- | --- | --- |
| BR-001 | 迁移不得改变 API 路径、方法、参数位置和响应解析语义 | 所有生产页 | 停止合并并修正 |
| BR-002 | 权限规则必须绑定当前抽屉菜单 ID | 数据/API 权限 | 阻止提交并重新加载上下文 |
| BR-003 | 菜单查询与权限子表查询不得共用状态对象 | 数据/API 权限 | 设计退回评审 |
| BR-004 | 数据权限类型及默认字段映射保持现有业务语义 | 数据权限 | 阻止提交并提示重新确认 |
| BR-005 | API 权限路径不得由前端自动归一化或改写 | API 权限 | 使用服务端原值重新加载 |
| BR-006 | 权限前端显示控制不是安全边界 | 权限与区划操作 | 服务端必须执行最终校验 |
| BR-007 | 区划完整编码按现有父编号与子编号契约生成，根编号 `00` 不作为编码前缀，层级不得超过 5 | 行政区划 | 阻止提交并定位错误 |
| BR-008 | 区划节点移动、级联删除和主键变更不得由前端自行推断 | 行政区划 | 交由后端契约并记录结果 |
| BR-009 | 示例页无批准下线结论时默认保留原入口并替换 | 工具示例 | 不允许直接删除 |
| BR-010 | 目标页不得重建列 JSON 驱动的 CRUD/Form 引擎 | 所有目标页 | 设计退回评审 |
| BR-011 | 普通接口错误由 `axios.ts` 统一提示，页面只负责恢复局部状态 | 所有生产页 | 移除重复错误提示 |
| BR-012 | 未取得真实访问证据时权限类 AC 不得标记通过 | 验收与文档 | 标记阻塞或未执行 |

### 7.3 后续权限影响

- 本需求默认不新增权限资源和权限码。
- 数据/API 权限抽屉内 CRUD 当前缺少独立前端按钮权限码，是否补充需与后端资源同步另行确认。
- 行政区划 Controller 当前未体现与前端 `region_*` 按钮一一对应的操作级注解，必须在开发前核实网关、菜单或服务层
  的实际保护，不得把前端隐藏按钮当作充分授权。
- API 权限路径的服务端包含匹配可能产生宽匹配风险，本阶段保持兼容并记录，不在前端静默修改。
- 数据/API 权限修改会清理系统缓存并可能影响在线访问，测试必须使用受控规则和角色，禁止修改生产共享规则。
